## 1. 事前準備（着手前にこれを揃える＝往復の8割が消える）

### 1.1 データを「個票レベル」で先に確定させる
今回最大の詰まりは、Kaizen リストを**1件ずつ ClickUp から取得**したこと、かつ集計タイルの
**個票 ID が手元になく**「その他・横断80件」等を後から取り込めなかったこと。

**やること：**
- ClickUp リストを **CSV エクスポート**（または該当ビューを共有）し、着手前にリポジトリ内へ置く。
  - 最低限のカラム：`custom_id / name / status / tags / description / 対象軸 / テーマ / 施策候補ラベル`
- 「どの母集団をリスト化するか」を**最初に確定**（例：Traveler接点全部＋手段①候補、など）。
  後から「あれも入れて」が来ると全集計をやり直すことになる。
- GA4 数値・期間・Property ID は着手前に確定（`347074845`、matched 同期比較の原則）。

### 1.2 用語・トーンの合意（CLAUDE.md に既出、必ず参照）
- サービス名 **Veltra**、主語 **Traveler** に統一。個人名は社外共有時ロール記述。
- 「着手しない」→「優先度は後回し」、「遅延」→「リスケジュール中」等の**柔らかい表現**。
- **カタカナ横文字は避け、平易な日本語**に言い換える（「フロー体験×ディテール品質」→
  「予約の流れ全体を整える／画面ごとの見た目・使い心地を上げる」）。

### 1.3 「完成の定義（DoD）」を先に握る
下の §5 チェックリストを**着手前に共有**し、これを満たしたら完成、と合意しておく。

## 2. 構造の原則（カテゴリ1を潰す）

1. **結論 → 具体 → 論証（なぜ）の順**。背景・前提を末尾に置かない。冒頭の結論スライドで言い切る。
2. **MECE**：同じ内容を2箇所に書かない。「概要スライド」と「詳細セクション」が重複しがちなので、
   概要で示した塊は詳細で繰り返さない（例：手段①②の名前グリッドと各手段カードの二重掲載を排除）。
3. **セクションは絞る（目安4〜5）**。8個は「読む気しない」と言われる。統合できるものは統合。
4. **各大セクションは囲みボックス（`.secbox`）で括り、横幅を統一**。どの詳細がどのセクションの
   話か視覚的に分かるようにする。中は白サブカードで小分け。
5. **見出しは結論・具体を書く**。「俯瞰図」「詳細」「各論点の詳細」等のト書き・ラベル的見出しは禁止。
6. **問いの連鎖（Q1→Q2→Q3）**で論証する場合、問いに正対した1文で答える（答えになっていない要約はNG）。

---

## 3. データ整合の原則（カテゴリ2＝一番信用を落とす）

- **すべての合計が合うこと**。親の件数 = 子の内訳の和。全体 = 主対象 + 対象外。
  端数は「未分類・判定保留 N件」として**明示タイル**で見せ、必ず総数に一致させる。
- **リストの件数が変わったら、連動する数値を全部更新**：
  - 統計カード（総数／未完了／対応済み 等）
  - 絞り込みの「すべて N」バッジ（施策候補・テーマ両方）
  - 見出し・説明文中の「N件（うち未完了M件）」
  - 「42 open + 7 done = 49」のように**足し算が画面上で成立**する構成にすると破綻しない。
- スコープの異なる数字（全リスト集計 vs 抽出リスト）を**同じ行に混ぜない**。混ぜると「合ってない」と
  即指摘される。カード群は同一スコープで揃える。
- 数値には出典（GA4 期間・Property ID、ClickUp 取得時点）を付ける。

## 4. 可読性・UI 機能の既定値（カテゴリ4・6を先回り）

- **文字は小さめ・高密度**。本文・テーブルとも詰めて「1スクロールで見える量」を増やす。
  スケール変更はギャップ比率を保ち、下限は 11px 程度。
- **長い塊は句点で改行**。`<br>` 連打ではなく意味単位で改行。箇条書きの区切りは「：」で
  ラベル内の「・」と区別する（「決済・返金・バウチャー： 16」）。
- **一覧（テーブル）の既定機能**：
  - 各行**トグルで詳細**（「課題／打ち手／期待効果」の3カラム）。ClickUp の原文コピペではなく
    **要約**する。ターゲット優先で全行に付ける。
  - **各行に元チケットへの小リンク（↗）**。行トグルとリンククリックは分離。
  - **複数選択 OR フィルタ**（施策候補・テーマの2グループ、グループ間 AND）。
  - 状態トグル（未完了のみ）は**独立行**に。
  - フィルタボタンは小型・件数は「すべて」だけ表示。
- **どこから来たかを可視化**：全体マップ→リストに載せた塊に「▼ 掲載」印を付ける。
- 幅広セクションは**左ナビに被らない**設計（負マージン方式、位置指定で被せない）。左ナビ開閉トグルは
  `nav.js` に共通実装済み。目次は項目が少なければデフォルト展開。

## 5. 提出前チェックリスト（DoD）

- [ ] 結論 → 具体 → 論証 の順になっている
- [ ] セクションは4〜5個、重複なし（MECE）、各セクションが囲みボックスで括られ横幅統一
- [ ] 見出しはすべて結論・具体（ト書き・ラベル見出しなし）
- [ ] **全ての合計が合う**（親=子の和、全体=主対象+対象外、端数は明示）
- [ ] リスト件数と、統計カード・「すべてN」バッジ・説明文中の件数が**全て一致**
- [ ] テーブルは全行トグル詳細（課題/打ち手/期待効果・要約）＋チケットリンク＋複数選択ORフィルタ
- [ ] 文字は高密度、長文は句点で改行、区切りは「：」
- [ ] カタカナ横文字を平易な日本語に、トーンは柔らかく
- [ ] 用語は Veltra / Traveler 統一、個人名の扱いOK、フォント13px以上（UI再現内部は除く）
- [ ] 会話由来の語・改善ボースト・版数履歴など「やり取りの痕跡」を残していない
- [ ] 左ナビ登録（`nav.js` の SPOT_ITEMS・パンくず・検出変数）とデプロイ確認

## 6. 「1発」を狙う着手プロンプトのひな型

```
`spot/<file>.html` を作成し、spot ページ群の10番目として nav.js に登録して。

【データ】添付の ClickUp エクスポート（CSV）を母集団とする。リスト化対象は
「Traveler接点 全件 ＋ 手段①に効く候補（AC編集・オプション等）」。集計は全て
CSV の実数に一致させ、端数は「未分類」で明示。

【構造】結論→具体→論証の順。セクションは4つ（①取り組むミッション ②手段① ③手段② ④棚卸し）。
各大セクションは囲みボックスで括り横幅統一。重複は作らない（MECE）。

【一覧】各行トグルで「課題／打ち手／期待効果」（ClickUp descriptionを要約）、
各行にチケットリンク、施策候補×テーマの複数選択ORフィルタ、未完了トグルは独立行。
全体マップ→リスト掲載分に「掲載」印。

【文体】結論見出し・平易な日本語（横文字回避）・句点で改行・高密度・区切りは「：」・
Veltra/Traveler 統一・トーンは柔らかく（「着手しない」ではなく「優先度後回し」）。

【完成基準】docs/ux-doc-oneshot-guide.md の §5 チェックリストを満たすこと。
1機能=1コミットで、順次 main へマージ・Vercel デプロイ。
```

## 7. 運用のコツ（今回うまくいった点）

- **1論点=1コミット=1PR** で順次マージ・デプロイし、プレビューを見てもらう流れは有効だった。
  （ただし上記の事前準備があれば、各PRの手戻り自体が減る）
- 数値を変えたら、その場で**画面上の足し算が成立するか**を検算してからコミットする。
- ClickUp / GA4 は MCP で直接引ける。**着手時に一度疎通を確認**し、以降は黙って進める。
