    補足：どこで・どう計測／集計しているか、データ項目の定義

    どこで測っているか

    効果は本番 www.veltra.com のみで測ります（開発サーバは設定が違い数値が乖離するため判定に使いません）。効果判定はリリース前後の比較で行います。

    どう計測・集計しているか

    ・実ユーザー値（KPI①）：Google の CrUX（Chrome UX Report）History API から、実際にサイトを訪れた Chrome ユーザーの体感速度（p75）を週次で取得。
    ・ラボ値（補助）：PageSpeed Insights API で試験室的に日次取得（施策の即時反応を見る用）。
    ・収集は Google Apps Script が自動実行 → スプレッドシートに蓄積 → このダッシュボードが読み込み表示。

    「表示速度」の2つの層

    本プロジェクトの速度改善は2層で捉える。
    ・(A) ページ読み込み（このページ上部のCWV）：LCP/CLS等。PSI/CrUX で測定。
    ・(B) 操作フロー（「操作フローの速度」表）：予約モーダル展開・カレンダー遷移・検索応答・ACリスト描画など、クリック→反応/表示の速さ。PSIでは測れない。実ユーザーの反応速度は INP に集約されるが、どのフローが遅いかの切り分けには GA4 のカスタム計測イベント（フロントで performance.now() により2点間の経過msを測り GA4 に送信＝要フロント実装）やサーバ/APM 計測（API応答）を用いる。現状は調査チケットの実測ベースラインを表示し、継続計測は GA4 イベント実装後に反映する。

    データ項目の定義

    ・LCP（Largest Contentful Paint）：主要コンテンツが表示されるまでの時間。
    ・INP（Interaction to Next Paint）：タップ等の操作に画面が反応する速さ。
    ・CLS（Cumulative Layout Shift）：表示中のレイアウトのズレ量。
    ・TTFB（Time To First Byte）：サーバから最初のデータが返り始めるまでの時間。
    ・p75：全ユーザーを速い順に並べ、遅い方25%手前の値（75パーセンタイル）＝「大多数のユーザーが体感している水準」。

    目標値の根拠

    目標（LCP≤2.5秒／INP≤200ms／CLS≤0.1）は Google が定めた公式の合格基準（Core Web Vitals） です。ユーザーの離脱・体感に関する研究に基づく世界標準で、Google 検索のランキング評価にも使われます。恣意的に決めた値ではありません。
