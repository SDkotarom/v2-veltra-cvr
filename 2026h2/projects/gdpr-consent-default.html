Governance Briefing ・ 02 データ / リーガル

GDPR対応 / 同意の既定宣言 と 法務パッケージ切替

英語サイトで完成済みの「同意の既定宣言」と法務文書パッケージを、日本語サイトにも適用する。Phase 0 が最優先である理由と、なぜ順序を戻せないのかを共有するための方向性メモ。

優先度：最優先 主導：commons ／ サイト側調整：Kotaro 更新：2026-07-30
01

結論

日本語サイトは、ページ表示と同時に 同意前から外部へデータが出ている 状態にある。実測では 29 ホスト に接続し、12 個のクッキーが同意を取る前に書き込まれ、接続先のうち 13 社がプライバシーポリシー上に記載がない。

英語サイトは新しい法務パッケージで既にこの状態を解消済み。日本語サイトだけが取り残されている。

最初に着手すべきは Phase 0：同意の既定宣言。ここで「Veltra は同意を取るまで計測・第三者提供タグを発火させない」という既定を宣言してから、GA 統合・GTM 統合へ進む。この順序は戻せない ―― 既定を決める前にタグを動かすと、後工程が全部やり直しになる。

02

なぜやるか

Traveler の閲覧・行動データを外部ベンダーへ渡す行為は、個人情報保護法上の 第三者提供 にあたる。第三者提供には 3 年間の記録保存義務があり、「いつ・誰に・何を・どの同意根拠で渡したか」を説明できる状態を常に保つ必要がある。同意の既定を宣言しないまま計測タグが動き続けると、この説明責任を果たせない。

さらに、日本語サイトと英語サイトでは 管理者法人が異なる（東京 と ホノルル）。言語で管理者が違うという矛盾は、コンテナ統合の局面で必ず突き当たる。ここを曖昧にしたまま統合を進めると、どちらの法人がデータ管理者として同意を取っているのかが説明できなくなる。だから統合の前に、同意の既定と管理者の整理を先に片付ける。

要するに： これは「法令を守るための最低ライン」であると同時に、後続の GA 統合・GTM 統合を安全に進めるための 土台工事。土台がないまま上物を積むと崩れる。
03

Phase 構成（4 フェーズ）

二木さんブリーフの 4 フェーズ。上から順に着手する。番号が優先順位であり、Phase 0 を完了させないと Phase 1 以降は本来やり直しになる。

PHASE 0最優先

日本語ページで「同意の既定」を宣言する

「同意を取るまで計測・第三者提供タグは発火しない」を既定として宣言し、同意管理の土台を日本語サイトに敷く。ここが全ての起点で、以降のフェーズはこの宣言の上に載る。

PHASE 1高

GA の日本語プロパティを 1 本にする

複数に分かれた日本語計測プロパティを 1 本へ集約し、同意の既定に沿った計測に揃える。データの持ち主と流れをシンプルにしてから次へ進む。

PHASE 2中

GTM コンテナを新しい作りへ寄せる

現行コンテナを、同意の既定を前提とした新コンテナの作りへ統合していく。第三者提供データの棚卸し（40 社台帳）はこの工程の準備にあたる。→ GTM統合ブリーフィング

PHASE 3低

統制を恒久運用に載せる

新規タグの追加・同意設定のチェックを、一度きりの整理で終わらせず継続運用の仕組みに載せる。棚卸しと承認のフローを定常業務化する。

04

Kotaro の担当範囲

この案件は commons が主導する。Kotaro は主導ではなく、二木さんからの実装依頼に応じて サイト側の調整を担当する立ち位置。

  • Phase 0 の宣言そのものの設計・法務判断は commons 側。Kotaro はサイト側で必要な実装反映を引き受ける。
  • 7/30 のオリエンで、サイト側実装のスコープを確定する。ここで受け取る範囲が Kotaro の実タスクになる。
  • スコープ確定後の分岐（実装が軽い / 重い / 担当外）に応じて、本ページに実装タスクを追記するか、別ページを新設する。

05

着手前に決まっていない点（意思決定待ち）

下記が決まらないと後工程が動かせない。オリエン・関係チームで順次確定させる。

管理者法人の統一
データ管理者を東京 と ホノルルのどちらに寄せるか。統合時に必ず突き当たる論点。
excl. Yokka の廃止可否
現行の除外設定を廃止してよいか。計測の連続性に影響する。
社外 20 名の GA 権限
社外アカウントの GA アクセス権をどう整理するか。権限は最小化の方針。
期限 2026-08-05
法務ページの切替タイミング
法務 13 文書パッケージを日本語サイトへ適用する時期。旧 URL の転送設計とセット。
旧 URL の転送設計
旧法務ページの URL をどこへ転送するか。SEO と被リンクの維持を含む。
コンビニ・ATM 支払い案内の移設先
法務ページ切替に伴い、支払い案内コンテンツをどこへ移すか。
セキュリティ観点： 社外の GA 権限は「必要な人・必要な範囲だけ」に絞る（アクセス権の最小化）。棚卸しの過程で、期限切れ・用途不明の権限は停止を既定とする。
