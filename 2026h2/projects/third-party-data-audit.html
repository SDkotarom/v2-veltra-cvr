これは GDPR対応 Phase 2（GTMコンテナ統合）の準備工程

第三者提供データの棚卸し（40社台帳更新）

GTM コンテナ内 286 タグのうち、外部へデータが出ていく送信先を台帳で棚卸しする。管理者不明・要判断の ★付き 7 件を優先し、Kotaro が正式責任者として台帳の記入を進める。無回答の送信先は停止を既定とする（社長承認済み）。

優先度：高 担当：Kotaro（単独記入方針） 更新：2026-07-30
01

結論

GTM コンテナ内の 286 タグを棚卸し対象とし、そのうち 管理者不明・要判断の ★付き 7 件を最優先で片付ける。これは第三者提供データの台帳（40 社規模）を「いつ・誰に・何を渡しているか」説明できる状態に更新する作業。

記入は Kotaro が正式責任者として単独で進める。台帳の R / S / T 列（用途・停止可否・対応方針）を、ヒアリング結果に基づいて埋めていく。

ヒアリングに無回答の送信先は「停止」を既定とする（社長承認済み）。「誰も用途を説明できないタグ」は、動かし続けるより止める方が安全。停止は削除ではなく Pause で統一し、記録を残していつでも戻せる状態にする。

02

この棚卸しの位置づけ

この作業は単独のタスクではなく、GDPR対応 Phase 2（GTMコンテナを新しい作りへ寄せる）の準備工程にあたる。統合の前に「何を外部へ渡しているか」を台帳で確定しておかないと、新コンテナへ移すべきタグ・止めるべきタグの判断がつかない。

  • Phase 0（同意の既定宣言）と並行して進められる ―― 棚卸しは掃除であり、Phase 0 の土台を妨げない。→ GDPRブリーフィング
  • GTM の断捨離と表裏一体 ―― 管理者不明タグのヒアリングは、断捨離の「いま進めていいこと」に含まれる。→ GTM統合ブリーフィング
  • 個人情報保護法の第三者提供記録（3 年保存義務）を満たすための、説明可能性の担保でもある。
03

優先 ★7 件 ― 台帳に書くこと

個社名・台帳シートの URL は非公開（社長指示）。ここでは記入すべき列と判断基準を共有する。★7 件は「管理者不明」または「送信先の性質が要判断」のタグ。

台帳列何を書くか判断基準
R 列 用途・データ内容 そのタグが何を計測し、外部の誰へ何を渡しているか。ヒアリングで判明した用途を記入。 「用途を 1 文で説明できるか」。説明できないものは要停止候補。
S 列 停止可否 止めても事業影響がないか。可 / 不可 / 要確認 を記入。 回答あり＝管理者判断に従う。無回答＝停止（既定）。
T 列 対応方針 Pause / 新コンテナへ移設 / 継続 のいずれか＋実施予定。 Phase 0 完了前は Pause か据え置きのみ。移設は Phase 2 で。
無回答の既定： 期限までに用途の回答が得られない送信先は S 列「停止」、T 列「Pause」で確定する（社長承認済み）。用途不明のまま外部へデータを出し続ける状態を残さない。
04

ヒアリング・停止フロー（4 フェーズ）

FLOW 1

対象の確定

286 タグ → 管理者不明・要判断を抽出 → ★7 件を最優先に並べる。台帳の未記入行を洗い出す。

FLOW 2

ヒアリング投稿

8/5〜 予定

各タグの管理者候補へ、用途・停止可否を確認する投稿を出す。回答期限を明示し、無回答時は停止になる旨を添える。投稿文は下記テンプレートを使用。

FLOW 3

記入・判定

回答を台帳の R / S / T 列へ記入。回答ありは管理者判断に従い、無回答は「停止」で確定する。

FLOW 4

停止実行と記録

停止対象を GTM 上で Pause に統一。「作成 → 確認 → 削除」の規律を守り、削除は棚卸し完了後にまとめて。停止記録を残し、いつでも戻せる状態にする。

05

ヒアリング投稿文（テンプレート）

送信先タグの管理者候補へ送る確認メッセージ。個社名・シート URL は入れず、対象タグ ID と用途確認だけを尋ねる。

Slack ／ One Trust & GTM Tag optimize project 投稿ドラフト
【GTM タグ棚卸しのお願い ― 用途確認】 計測・データ取り扱いの健全化（GDPR ほかリーガル対応）の一環で、GTM コンテナ内のタグを棚卸ししています。以下のタグについて、心当たりのある方は用途を教えてください。 ■ 対象タグ：（タグ ID / 名称を記載） ■ 教えてほしいこと 　1. このタグは何を計測し、どこへデータを送っていますか 　2. いま止めても事業影響はありますか（可 / 不可 / 要確認） ■ 回答期限：（日付） ■ 期限までに用途の回答が得られない場合は、安全側に倒して当該タグを「停止（Pause）」します（停止であり削除ではないため、必要なら後から戻せます）。この扱いは承認済みです。 用途が分かる方が他にいれば、この投稿を回していただけると助かります。
書き方の既定： 個社名で名指しせず、タグ ID で照会する。台帳シートの URL は貼らない（社長指示）。特定ベンダーへの批判的な表現は避け、あくまで「用途の確認」に徹する。
