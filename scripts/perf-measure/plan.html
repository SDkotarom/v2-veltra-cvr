目的

  • リリースで「速くなった」ことを、動画と数字の両方で示す
  • 速くなった結果、Traveler の動きがどう変わったかを、CVR より手前の指標で見る（一覧からAC詳細へ進む割合、2ページ目へ進む割合など）

比べ方

前後比較

リリース前（11/4〜12/1）とリリース後（12/3〜12/30）を、曜日をそろえて比べる。

変えていないページとの比較

今回変わるのはエリア版カテゴリー（type B）。全国版カテゴリー（type A）は変わらないので、同じ期間の動きと比べる。12月は繁忙期で数字が全体に動くため、その影響をここで差し引く。

録画の手順（リリース前と後で同じ条件）

  1. Chrome で新しいシークレットウィンドウを1つ開く
  2. Command + Option + I を1回押して、開発ツールを開く
  3. 開発ツール左上の端末アイコンを1回押して、スマホ表示にする（機種は毎回同じものを選ぶ）
  4. 「ネットワーク」タブの「キャッシュを無効化」に1回チェックを入れる（ブラウザ側の保存を使わず、サーバー側の効果だけを見るため）
  5. Command + Shift + 5 を1回押して、画面収録を始める
  6. 京都バスツアーの1ページ目を開き、一覧が出るまで待つ
  7. 画面下のページ番号「2」を1回押し、一覧が出るまで待つ
  8. 検索結果ページ（tokyo）を開き、一覧が出るまで待つ
  9. 収録を止め、ファイル名に日付を入れて GTM 書き出しと同じドライブのフォルダーに置く

同じページを2回続けて撮ると、2回目はキャッシュが効いた状態になる。リリース前・後ともに「1回目」と「2回目」を両方撮っておく。

追加の仕込み（GTM）

一覧が表示されるまで待った時間を、実ユーザーの数字として GA4 に送る。くるくるが出ていた時間がそのまま数字になる。

  • イベント名：list_ready　パラメータ：wait_ms（ページを開いてから一覧の商品カードが出るまでのミリ秒）、page_type（category_area / category_nationwide / search）、page_no
  • 仕組み：GTM のカスタム HTML で、一覧の商品カードが画面に入った時刻を記録して送る
  • 必要なもの：一覧の商品カードを指す HTML の目印（class 名など）。本番ページのソースで確認が必要
  • 公開：GTM の公開権限を持つ人が行う

リリース前のデータを取るため、12/1 までに公開できるのが望ましい。間に合わない場合も、リリース後の数字を全国版（変わらないページ）と比べることはできる。
