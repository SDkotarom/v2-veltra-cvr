# カテゴリー・検索の改善案：相談メモ（2026-10-21）

## 相談したいこと

1. **進め方の確認。** キャッシュの作成周期・表示内容の鮮度についてユーザー体験に影響があるためTeppeiさんにもご相談したい。
2. **どの案から着手するか。** 下の6案のうち、先にやる案を決めたい。牧野の案は次のとおり。
   - **先にやる：** ①（カテゴリー1ページ目を、24 時間のページキャッシュにする）と、⑤（検索の処理の調査。検索 API は 3 秒未満なのに、最初の応答は 5 秒超で、約 2 秒の差がある。その原因を調べる）。2つとも、保存する量を大きくは増やさない見込み（未確認）で、先に始めやすい。
   - **次にやる：** ③（絞り込み結果のキャッシュ。よく使われる絞り込みだけに範囲を絞る）。
   - **容量の確認後に決める：** ②（2ページ目以降のキャッシュ。全部で 1.6GB 超の見積もり）。

   この順番でよいか、意見がほしい。
3. **①の古さ。** カテゴリー1ページ目を最大 24 時間古くしてよいか。価格・在庫・セールの表示が古くなる。
4. **効果の見方。** CVR の手前の指標（離脱、商品ページへの到達など）で見る案。指標と、成功の基準を、決めたい。詳細は `effect-metrics-design.md`。

## 6案の一覧

| 番号 | 対象 | 案 | メリット | デメリット・懸念 |
|---|---|---|---|---|
| ① | カテゴリー | カテゴリー1ページ目を、24 時間のページキャッシュにする | リングが出ない。速い。Sightseeing_Tour のページが、すでに同じ方式 | 古いデータが最大 24 時間出る（特別セールなど） |
| ② | カテゴリー | 2ページ目以降を、30 分単位でキャッシュする | キャッシュがあれば速い | 全部で 1.6GB 超の見積もり（Suki さん）。2ページ目以降を見る人の割合は未確認 |
| ③ | カテゴリー | 絞り込み結果を、30 分単位でキャッシュする | キャッシュがあれば速い | 組み合わせが多く、当たる割合が読めない。範囲を絞る案：よく使われる絞り込みだけ、日付 1 日だけ |
| ④ | 検索 | 検索ページの枠を先に出し、結果は後から描画する | 最初の応答が速くなる | 表示のずれ（原文は CLP、CLS の誤記と思われる）。仮の枠のデザインが要る。検索 API の改修が要る |
| ⑤ | 検索 | 検索ページと filter_kw() の ajax を最適化する | キャッシュに関係なく速くなる | 原因が未特定。検索 API は 3 秒未満、最初の応答は 5 秒超で、差が約 2 秒 |
| ⑥ | 検索 | よく検索されるキーワードを、定期実行で先にキャッシュする | よく検索されるキーワードが、いつでも速い | 珍しいキーワードには効かない。定期実行の仕組みが新しく要る |

## 補足

- **キャッシュの保持時間と容量。** 保持時間を長くしても、同時に残るキャッシュが増えるため、容量は減らない見込み（牧野の推測、未確認）。1.6GB は「全部保存したら」の上限の見積もり。
- **2ページ目以降を 24 時間にしない理由。** Suki さんの投稿に、理由の記載がない。古さを避けるため、という牧野の推測は、確認していない。
- **関連する実測。** 検索の実ユーザーの最初の応答は 5.5 秒（10/3 の週）。カテゴリーの絞り込みは、UX_DESIGN-309 で、平均 1.82 秒から 0.97 秒（手計測 10 回）。
