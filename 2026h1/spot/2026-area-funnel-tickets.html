T-A5ジャンルから探す（常時ボタン・KKday型）① 自分で探す規模：小
概要 / Overview

エリアページの「探す」直下に、種別（観光ツアー・アクティビティ・チケット・交通・グルメ 等）のアイコンボタンを 5〜7 個 常時表示し、種別起点で能動的に探せる入口を作る。タブに隠さず、エリア×ジャンルの既存一覧へ送る。

狙う層・KPI・戦略軸
  • 層③ 方向だけ
  • Primary KPI有効AC到達率
  • 戦略軸メインスポット取りこぼし防止
仮説 / Hypothesis
  • 課題種別起点で探したい入口が無い。絞り込みがタブやモーダルに隠れると気づかれず、受け身でランキングを眺めて離脱する
  • 打ち手探すユニット直下に 5〜7 個のジャンルボタンを常時表示し、1タップでエリア×ジャンル一覧へ
  • 期待成果能動的な探索が増え、一覧→AC到達が伸び、有効AC到達率が上がる
ユーザーストーリー & 受け入れ条件
As a Traveler、エリアページを開いたとき、まず「どんな種類の体験があるか」を一目で選びたい。so that 自分の関心（チケットだけ・交通だけ 等）に最短で辿り着ける。
  • Given エリアページ表示、When ファーストビュー付近、Then 探す直下にジャンルボタンが 5〜7 個、常時表示されている
  • Given ジャンルボタンをタップ、When 遷移、Then そのエリア×ジャンルの既存一覧が開く（新規画面を作らない）
  • Given エリアごとに需要構成が違う、When 表示、Then 並び順がそのエリアの需要の大きい順
  • Given タップ、When 計測、Then genre_btn_click(genre, position) 発火
  • SP（390px幅）で横スクロールや崩れが無い
詳細仕様
  • 配置探すユニット（T-SEARCH）の直下。タブに隠さず常時表示。アイコン＋ラベルを 5〜7 個
  • ジャンル種別既存グローバルナビのカテゴリ体系を流用（観光ツアー／アクティビティ／チケット／交通・移動／グルメ／eSIM・WiFi 等）
  • 並び順エリアごとに需要の大きい順（リゾート＝アクティビティ/チケット上位、都市＝グルメ/交通上位）。月次バッチで予約実績（DWH/BigQuery）を集計しエリア別の並び順データを生成、フロントが参照
  • 着地エリア×ジャンルの既存一覧ページ（新規開発なし）
  • 不採用「条件でしぼる（A-4）」はこの画面では不採用。ジャンル×条件はカテゴリページ（C-1／C-4）で実施

T-A3ランキング切り口タブ（共通3＋エリア可変N）② おすすめ規模：中
概要 / Overview

おすすめゾーン先頭の「ランキング」を、固定の売れ筋一本から 切り口タブ に拡張。全エリア共通3切り口（売れ筋・満足度・急上昇）＋エリアのデータが充足したときだけ可変タブ（子連れ・直前OK・テーマ）を自動追加。各タブはインラインのACカルーセル（10件＋すべて見る）で、その場のタップ＝AC到達。

狙う層・KPI・戦略軸
  • 層③ 方向だけ
  • Primary KPI有効AC到達率
  • 戦略軸メインスポット取りこぼし防止
仮説 / Hypothesis
  • 課題ランキングが売れ筋・満足度の固定でいつ見てもほぼ同じ。時期や自分に合うかが分からず素通りされる
  • 打ち手切り口タブで複数の見せ方を用意し、時期で動く「急上昇」やエリアに合う可変タブで新候補に出会わせる
  • 期待成果ランキングCTRと Top外（4位以降）のAC到達比率が上がり、有効AC到達率が上がる
ユーザーストーリー & 受け入れ条件
As a Traveler、エリアのおすすめを見るとき、売れ筋以外の切り口（評価が高い・いま伸びている・自分の条件に合う）でも見比べたい。so that 定番以外の自分に合うACに出会える。
  • Given おすすめゾーン先頭、When 表示、Then 共通3タブ（売れ筋／満足度／急上昇）、初期は売れ筋
  • Given 各タブ、When 表示、Then タブ直下にキャッチ1行（「いちばん予約されています」等）
  • Given タブをタップ、When 切替、Then そのタブのACカルーセル（最大10件＋すべて見る）が即時切替
  • Given エリアのデータが充足、When 表示、Then 該当エリアにだけ可変タブ（子連れ／直前OK／テーマ）を自動追加。データ不足エリアでは非表示
  • Given ACカードをタップ、When 遷移、Then AC詳細へ到達（タップ＝AC到達）
  • Given タブ切替、When 計測、Then ranking_tab_switch(tab) 発火
詳細仕様
  • 配置おすすめゾーン先頭（ファーストビュー近く）。表示形式インライン（ACカルーセル 10件＋すべて見る）
共通切り口（全エリア）キャッチデータ
売れ筋いちばん予約されています直近30日の予約数（既存）
満足度クチコミ評価が高い順体験談の評価（既存）
急上昇予約が急に伸びています予約数の前週/前月比の伸長（季節ものを拾う）
可変切り口（データ充足時のみ）キャッチ出す条件
子連れに人気お子さま連れに人気家族予約比率・体験談「子ども」言及が一定以上のエリアのみ
直前でも取れる今日・明日に参加できる当日〜翌日在庫があるACが一定数あるエリアのみ
テーマ（海/自然/文化…）—そのエリアの主力テーマに応じて1〜2本

出し分けロジック：共通3＋可変N。可変タブは月次バッチでエリアごとのデータ充足を判定して自動で出し入れ（固定で全部出さない）。データソースは予約実績・体験談・在庫（DWH/BigQuery＋在庫データ）。売れ筋・満足度・急上昇は「実績データ×普遍的な切り口」でどのエリアでも成立。子連れ・直前OK・テーマはエリアの在庫・客層に依存するため、合わないエリアでは0件や的外れになる。

  • Variant切り口タブ（共通3＋可変N）
  • 任意アーム可変タブ有無の比較
  • 対象Site: JP／Device: Mobile・PC

T-A7ジャンル別おすすめ（カテゴリ別の人気AC行）② おすすめ規模：中
概要 / Overview

おすすめゾーンに、カテゴリごとの人気ACを 横1列×複数行 で積む（半日・1日ツアー／チケット／交通／グルメ…）。各行右に「すべて見る」。ランキングや単一おすすめだけでは見えないエリアの多彩さを、実ACカードで見せて回遊とAC到達を増やす。

狙う層・KPI・戦略軸
  • 層③ 方向だけ
  • Primary KPI有効AC到達率
  • 戦略軸メインスポット取りこぼし防止
仮説 / Hypothesis
  • 課題ランキング／単一のおすすめだけだと、自分の興味カテゴリのACに辿り着きにくく、エリアの多彩さ（チケット・交通・グルメ 等の幅）が見えない
  • 打ち手カテゴリ別に人気ACを横1列ずつ複数行で積み、興味カテゴリの行で実ACに直接出会わせる
  • 期待成果おすすめ経由のAC到達と、行間の横移動（回遊）が増える
ユーザーストーリー & 受け入れ条件
As a Traveler、エリアのおすすめを見るとき、種類ごと（ツアー・チケット・交通…）に実際のACを数件ずつ眺めたい。so that 1本のランキングに縛られず、自分の興味カテゴリのACにそのまま出会える。
  • Given おすすめゾーン、When 表示、Then カテゴリごとに横1列（3〜5件）＋「すべて見る」が複数行で積まれている
  • Given 行の選定、When 表示、Then そのエリアで予約が多いカテゴリ順の上位（在庫AC5件以上のカテゴリのみ）が並ぶ
  • Given 各行のAC、When 表示、Then そのカテゴリの既存の並び順（売れ筋）上位5件がそのまま使われる（新規の並び替えをしない）
  • Given ACカードをタップ、When 遷移、Then AC詳細へ到達
  • Given 「すべて見る」をタップ、When 遷移、Then そのカテゴリ一覧へ
  • Given タップ、When 計測、Then genre_row_card_click(category_id, position)／genre_row_seeall_click(category_id) 発火
詳細仕様
  • 配置おすすめゾーン（人気カテゴリ・あなたにおすすめの近傍）。表示形式インライン（カテゴリ別ロー×複数）
  • 束ねる軸既存のカテゴリ分類をそのまま流用（新規タグ付け不要）
  • 行（ジャンル）の選定そのエリアで予約が多いカテゴリ順の上位6（在庫AC≥5のカテゴリのみ・月次更新）。リゾートと都市で並ぶカテゴリが変わる
  • 各行のACそのカテゴリの既存の並び順（売れ筋）上位5件をそのまま使用（新規の並び替えロジック不要）
  • データ生成月次バッチで予約実績（DWH/BigQuery）からエリア×カテゴリの予約ランクを算出し、行構成データを生成してフロントが参照
テストパターン / Test Variations
  • Control現行（ジャンル別おすすめ行なし）
  • Variantカテゴリ別の人気AC行を複数表示
  • 任意アーム行数（3行 vs 6行）で情報過多を検証
  • 対象Site: JP／Device: Mobile・PC
指標 / Metrics
Primary
  • 有効AC到達率
Sub

  • 回遊（複数ジャンル行の閲覧率・行間横移動）

Guardrail

T-SEARCH探す検索ユニット（A-8 サジェスト＋A-2 人気検索ワード＋A-6 日付・いますぐ）① 自分で探す規模：大
概要 / Overview

エリアページ最上部に「自分で探す」を1箇所に集約する薄いタブ（常に1タブ分だけ表示）。タブ1＝行き先・キーワード（タップで検索サジェスト＝検索履歴／人気の検索ワード／人気スポット を展開）、タブ2＝日付・いますぐ（このエリア固定で 今日・明日・日付指定）。空欄でも候補が出て、日付・直前ニーズの入口も用意する。

狙う層・KPI・戦略軸
  • 層③ 方向だけ（＋直前型を一部回収）
  • Primary KPI有効AC到達率
  • 戦略軸メインスポット取りこぼし防止
仮説 / Hypothesis
  • 課題検索窓は入力前提で、空欄のままだと何も起きず素通り。何で検索すればいいか分からない人が離脱。日付・現地ですぐ参加したい直前ニーズの入口が無い／埋もれる
  • 打ち手検索窓タップでサジェスト（履歴・人気ワード・人気スポット）を展開し、空欄でも1タップで結果へ。日付・いますぐタブで直前ニーズの入口を最上部に
  • 期待成果検索開始（現状6.6%・モバイル7.1%）の裾野を回収し、検索・日付経由のAC到達が増え、有効AC到達率が上がる
ユーザーストーリー & 受け入れ条件
As a Traveler、検索窓に触れたとき、何を入れればいいか分からなくても候補（よく探される言葉・人気スポット・過去の検索）を見たい。so that 入力に迷わず1タップで一覧へ進める。
As a Traveler（現地・直前）、今日・明日に参加できるものを最上部からすぐ探したい。so that 滞在中の直前ニーズで取りこぼされない。
  • Given 最上部、When 表示、Then 薄いタブ（行き先・キーワード／日付・いますぐ）が常に1タブ分だけ表示され、画面を占有しない
  • Given 行き先・キーワードタブ、When 検索窓をタップ、Then サジェスト展開：①検索履歴 ②人気の検索ワード ③人気スポット
  • Given 人気の検索ワード、When 表示、Then エリア×直近90日のサイト内検索 上位5語（体験・条件語に限定）
  • Given サジェストをタップ、When 遷移、Then エリア絞込済のサイト内検索結果へ
  • Given 日付・いますぐタブ、When 表示、Then このエリア固定で 今日・明日・日付指定（エリア変更は無し）
  • Given 日付を選ぶ、When 遷移、Then 既存の日付フィルタ付き一覧へ（新規画面なし）
  • Given 各操作、When 計測、Then find_tab_switch／search_focus_open／suggest_chip_click／date_search_submit 発火
詳細仕様
  • 構成薄いタブ（常に1タブ分だけ表示・遷移型）。タブ1＝行き先・キーワード（初期表示）、タブ2＝日付・いますぐ
  • A-8 検索サジェスト検索窓タップで展開。①検索履歴（端末保持）②人気の検索ワード ③人気スポット（既存の人気カテゴリ由来）。本文の他ブロックと重複してよい
  • A-2 人気の検索ワードサジェスト内に表示。データ＝エリア×直近90日のサイト内検索 上位5語（季節性×安定性の折衷・月次）。リンク先＝サイト内検索結果（エリア絞込済）。スポット名は人気スポットに任せ、ここは体験・条件語に限定
  • A-6 日付・いますぐこのエリア固定で 今日・明日・日付指定。着地＝既存の日付フィルタ（today/tomorrow/指定）。件数は当日〜翌日在庫から算出
  • 不採用「条件でしぼる（A-4）」はこの画面では不採用（→ カテゴリ C-1／C-4）
  • 設計考察既存軸の昇格（子供と・半日で）は「条件」と語彙が重複し価値が薄い。検索実需チップは ①Traveler の言葉（「天国の海」等はベルトラ分類に無い）②実需準拠で当たりやすい ③時期で自動入替 ④検索開始の入力負荷を肩代わり、で採用。検索ボックスの隣に置くのが要点
