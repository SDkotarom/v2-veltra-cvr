「前提：流入モデル」を Braze で実装する｜ページ別パーソナライズ 方法別まとめ
結論
問い：流入モデルの「開催エリア／カテゴリーページから、一部の人にだけ野球LP導線を出す」を、Braze でどう実装するか？
答え：まず「誰に出すか」を1つの共通基盤（野球意図シグナル → Braze のカスタム属性）で作り、その上に面ごとのテンプレを4種載せる。全画面モーダルは使わず、対象は野球意図シグナルを持つ Traveler に限定（スポーツ全体には出さない）。
①スリムバナー
In-App Messageエリア／カテゴリー／AC詳細の下部に、閲覧中その場で表示。ファーストビューを覆わず閉じられる。即効・非侵襲な受け皿。
②コンテンツカード
Content CardsTOP／マイページのおすすめフィードに1枚常設。閉じても消えない永続枠で再訪 Traveler に効く。
③レコメンド枠差し込み
Connected Content野球AC閲覧後の関連枠に最新の野球AC上位3件を送信時に取得して差し込む。
④メール配信
CRM / Email閲覧者・購入者へサイト外から後追い。文面は球団／選手名でパーソナライズ。
戦略軸：意図ある新規の取りこぼし防止（離脱させず AC 送客）。
共通基盤（GA4 → Braze 属性）を1回作れば、面の追加・文面変更は Braze ダッシュボードのノーコード操作で回せる。「誰かが手で選ぶ」運用にはしない。
概要：4つの方法の使い分け

「どこに・誰に・何のために出すか」を面ごとに整理。すべて同じ1つのセグメント（baseball_intent = true）を条件に使うので、共通基盤は1回作れば全方法で共有できる。

方法Braze機能出すページ誰に役割
① スリムバナーIn-App Message（Web・バナー型）開催エリア／カテゴリー／AC詳細 の下部閲覧中に野球意図が立った Travelerその場で野球LPへ送る（即効）
② コンテンツカードContent CardsTOP／マイページのおすすめフィード直近14日に野球ACを見た再訪者常設枠で再訪時に想起
③ レコメンド枠差し込みConnected Content（送信時に外部API取得）野球AC閲覧後の関連レコメンド枠野球AC閲覧直後の Traveler最新の野球AC上位3件を提示
④ メール配信Email（イベントトリガー配信）メール（サイト外）野球AC/カテゴリ閲覧者・過去購入者離脱後の引き戻し

読み方

以下、まず全方法の土台となる「共通基盤」（誰に出すかを決める仕組み）を設計し、そのあと方法①〜④それぞれで「結論 → 詳細 → 設定手順・コード」の順にドリルダウンする。

基共通基盤：野球意図シグナル → Braze 属性（全方法の土台）
結論：「誰に出すか」はGA4 のイベントを Braze のカスタム属性に写すことで決める。
鮮度が要る「直近閲覧」はWeb SDK でその場更新（バッチを待たない）、購入履歴など重い集計は日次バッチで流し込むハイブリッド。データ蓄積を待たず、静的セグメントで即日スタートできる。

4. リアルタイム属性更新（Web SDK・GTM 経由）

SDK は GTM のカスタムHTMLタグで全ページに1回読み込む。閲覧中に意図が立った瞬間、バッチを待たずその場で属性を更新する。

① SDK 初期化（GTM カスタムHTMLタグ / 全ページ共通）
// Web API Key は公開前提でOK。REST API Key は絶対にフロントへ置かない。 import * as braze from "@braze/web-sdk"; braze.initialize(BRAZE_WEB_API_KEY, { baseUrl: "sdk.iad-05.braze.com", // 契約クラスタに合わせる enableLogging: false }); braze.automaticallyShowInAppMessages(); // In-App を自動表示（方法①の土台） braze.openSession();
② 野球AC詳細ページで発火（例：ロサンゼルス／ドジャース）
braze.logCustomEvent("baseball_ac_view", { ac_id: "AC12345", team: "dodgers", area: "los-angeles" }); // 出し分け用の属性も即時更新（＝当日から効く） const u = braze.getUser(); u.setCustomUserAttribute("baseball_intent", true); u.setCustomUserAttribute("baseball_last_viewed_at", new Date().toISOString()); u.setCustomUserAttribute("baseball_fav_team", "dodgers"); u.setCustomUserAttribute("baseball_viewed_area", "los-angeles"); braze.requestImmediateDataFlush();
5. 日次バッチ（GA4 集計 → Braze 投入）のクエリと実行環境

用途：閲覧の鮮度は SDK が担うので、バッチは購入履歴・過去の閲覧集計など重い属性を担当。実行環境：Cloud Scheduler（毎日 05:00 JST）→ Cloud Functions（Python）→ Braze REST API。

BigQuery：直近30日に野球ACを見た Traveler を抽出
-- GA4 export（Property 347074845）× 野球AC マスターで判定 SELECT user_id AS external_id, MAX(event_timestamp) AS last_view_ts, LOGICAL_OR(m.purchased) AS purchased FROM `veltra.analytics_347074845.events_*` e JOIN UNNEST(e.event_params) p ON p.key = 'ac_id' JOIN `veltra.ac_master.baseball_ac` m ON m.ac_id = p.value.string_value WHERE _TABLE_SUFFIX BETWEEN FORMAT_DATE('%Y%m%d', DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)) AND FORMAT_DATE('%Y%m%d', CURRENT_DATE()) AND e.event_name = 'view_item' GROUP BY external_id
Cloud Functions：Braze REST /users/track へ投入
# REST キーは Secret Manager から取得（ハードコード禁止・最小権限） import requests KEY = access_secret("BRAZE_REST_KEY") rows = run_bigquery(SQL) attrs = [{ "external_id": r["external_id"], "baseball_intent": True, "baseball_ac_purchased": r["purchased"], } for r in rows] # /users/track は最大75件/リクエスト → チャンク送信 for chunk in chunked(attrs, 75): requests.post( "https://rest.iad-05.braze.com/users/track", headers={"Authorization": f"Bearer {KEY}"}, json={"attributes": chunk})

Braze への投入経路（まとめ）：リアルタイム属性／イベント＝Web SDK、重いバッチ属性＝REST /users/track、メール文面の最新AC＝Connected Content（送信時取得・方法③④）。

稼働責任（仕組みで自走）

初期セットアップ（1回）：エンジニアが GTM で SDK 設置＋カスタムイベント計測を実装し、Cloud Functions／Scheduler を構築。
以降：バッチは Cloud Scheduler で自走（マネージド）、面の追加・文面変更・出し分けは Braze ダッシュボードのノーコード操作で完結。セグメントは baseball_intent = true 等の条件で自動ターゲティングし、手で対象を選ぶ運用は発生しない。

セキュリティ・プライバシー配慮

① REST API Key／Connected Content の認証情報はコードに書かず Secret Managerで管理（Web API Key のみ公開可）。
② BigQuery アクセス用サービスアカウントは最小権限（BigQuery Data Viewer）に限定。
③ Traveler の識別は external_id（メール等の PII は Braze の会員ID／ハッシュで扱い、URL パラメータに個人情報を載せない）。
④ バッチの成否は Slack へ通知、カスタム属性辞書は Google スプレッドシートで一元管理し、実装と運用の前提をチームで共有する。

①スリムバナーBraze In-App Message（Web・バナー型）
結論：開催エリア／カテゴリー／AC詳細ページの下部に、野球意図が立った Traveler へその場で野球LPバナーを出す。ファーストビューを覆わず、×で閉じられる。意図が最も熱いその瞬間に送客できるので即効性が高い。
詳細
  • 発火：baseball_ac_view または baseball_category_view をトリガーに表示。
  • セグメント：baseball_intent = true かつ baseball_last_viewed_at が直近14日以内、かつ baseball_ac_purchased = false（購入済み除外）。
  • 制約：スリム型（画面下固定バナー）に限定し全画面モーダルは不可。同一 Traveler への表示は頻度制御（例：3日に1回まで）。

  • 手順2：Trigger を Custom Event baseball_ac_view に設定。
  • 手順3：Target Segment に上記の属性条件を設定。
  • 手順4：メッセージ本文を Liquid でパーソナライズ、CTA の遷移先を野球LP（エリアプリセット＋UTM付き）に。

  • 面：既存のおすすめフィード枠を SDK で描画。Braze から配信されたカードのうち野球LP用（extras.category = baseball_lp）だけを差し込む。
  • セグメント：共通基盤の baseball_intent = true（再訪でも属性が残るため常設に向く）。
  • 制約：フィードの一等地を占有せず1枚に留める。購入済みは baseball_ac_purchased で除外。

  • 手順1：Braze ＞ Content Cards を新規作成し、Key-Value ペアに category = baseball_lp と deeplink を設定。
  • 手順2：Target Segment を baseball_intent = true に。
  • 手順3：フロントで Content Cards を購読し、野球LP用カードだけを既存フィードに差し込む。

③レコメンド枠差し込みBraze Connected Content
結論：野球AC閲覧後の関連レコメンド枠に、Braze の Connected Content でVeltra 側の推薦APIから最新の野球AC上位3件を送信時に取得して差し込む。在庫・価格が動いても常に最新を出せる。
詳細
  • 仕組み：Connected Content ＝ Braze がメッセージ配信/表示のその瞬間に外部URLを HTTP GETして結果を本文に埋め込む機能。事前バッチ不要で最新値を出せる。
  • データソース：Veltra 推薦エンドポイント（external_id と baseball_viewed_area を渡し、野球AC上位3件を返す）。
  • 制約：取得先は認証必須（Basic 認証等）。APIが落ちた場合のフォールバック文言を必ず用意。
設定手順とコード
  • 手順1：Veltra 側に「野球AC上位3件」を返す推薦エンドポイントを用意（認証付き）。
  • 手順2：Braze メッセージ本文で Connected Content を呼び、返り値をループ描画。
  • 手順3：取得失敗時のフォールバック（固定の人気AC）を {% if %} で分岐。
