野球LP × Braze 設定手順書

設計提案の「Braze パーソナライズ 4方法」を、実際に配信できる状態にするための手順。
GTM でタグを入れるだけで動く簡単なものから順に並べ、各ステップで「やること → 手順 → コード → 動作確認」まで載せる。

対象ページ: dev.veltra.com/jp/lp/sports/baseball/ 導入方法: GTM（Google Tag Manager） 前提: 設計提案の 方法①〜④
結論：この順で進める

まず STEP 0〜1（GTM で SDK を入れて、Braze 管理画面からバナーを1本出す）だけで最小構成が動く。ここまではコードもほぼ不要で、その日のうちに dev 環境で「Braze から野球LP導線を表示」を確認できる。
STEP 2 以降は「誰に出すか」を細かくする段階で、後になるほど開発工数が増える。下に行くほど難しく・重い。

安全のための原則

① dev で試す間は、GTM トリガーを野球LPのパスに限定（/jp/lp/sports/baseball/ を含む時だけ発火）し、サイト全体に影響を出さない。
② Web API Key はフロント公開前提でOKだが、REST API Key（STEP 5）はコードに書かず Secret Manager 等で管理する。
③ 会員のメール等 PII は URL パラメータに載せない。識別は external_id で行う。

0GTM で Braze Web SDK を入れるかんたん
ゴール：野球LPを開くと Braze SDK が読み込まれ、Braze 管理画面から In-App メッセージを出せる状態になる。全方法の土台。
やること
  1. GTM に カスタムHTMLタグを1つ作り、SDK 読み込み＋初期化コードを貼る。
  2. トリガーを野球LPのパスに限定して、対象ページだけで発火させる。
  3. GTM の プレビューで発火を確認し、公開する。
手順
  1. GTM ＞ タグ ＞ 新規 ＞ タグの種類「カスタム HTML」を選ぶ。
  2. 下記コードを貼る（YOUR_WEB_API_KEY と クラスタ URL を自分の値に置換）。
  3. トリガーで「新規 ＞ ページビュー ＞ 一部のページビュー」を選び、条件を Page Path 含む /jp/lp/sports/baseball/ に設定。
  4. プレビューで野球LPを開き、タグが発火することを確認 → 公開。
GTM カスタムHTMLタグに貼るコード
<!-- Braze Web SDK（CDN配信のUMDビルド。ビルド不要でGTMに貼れる） --> <script src="https://js.appboycdn.com/web-sdk/5.7/braze.min.js"></script> <script> braze.initialize('YOUR_WEB_API_KEY', { baseUrl: 'sdk.iad-05.braze.com' // ← 自社クラスタに置換 }); braze.automaticallyShowInAppMessages(); // In-App を自動表示（STEP 1 の土台） braze.openSession(); </script>

会員を識別したい場合（任意）

ログイン済み Traveler をメール等（STEP 4）で狙うなら、ログイン情報が取れる場所で braze.changeUser('外部会員ID') を呼ぶ。匿名訪問者のままでも In-App／Content Cards（STEP 1〜3）は動く。

✔ 動作確認
  • GTM プレビューで、野球LP表示時に当タグが Fired（発火）になっている。
  • ブラウザの Console で braze と打って オブジェクトが返る（読み込めている）。
  • Braze ＞ Manage Settings ＞ でデータ受信（sessions）が増える。
1In-App スリムバナーを1本出すかんたん
ゴール：野球LPの下部に「野球観戦ツアー特集」バナーを表示。まず全訪問者に出して疎通を確認し、次に出し分け（STEP 2）へ。Braze 管理画面の操作だけで完結（GTM 追加コード不要）。
手順（Braze 管理画面）
  1. Braze ＞ Campaigns ＞ Create ＞ In-App Message、チャネルは Web。
  2. レイアウトを Slideup（画面下部の細いバナー）にする（ファーストビューを覆わない）。
  3. Trigger を「Session Start」に設定（STEP 2 導入後は Custom Event に変更）。
  4. Target は最初「All Users」で疎通確認 → 確認後に Segment（STEP 2）へ絞る。
  5. 本文と CTA（下のコード）を設定し、CTA の遷移先を野球LP URL＋UTM に。
  6. Test 送信で自分の端末に表示 → Launch。
CTA の遷移先（経路計測 UTM 付き）
https://dev.veltra.com/jp/lp/sports/baseball/?utm_source=braze&utm_medium=inapp&utm_campaign=baseball_lp
本文を球団／選手名でパーソナライズする（STEP 2 の属性が前提）

STEP 2 で baseball_fav_team 等を送っていれば、Liquid で出し分けできる。属性が無い人には汎用文言が出る。

本文（Liquid）
{% if {{custom_attribute.${baseball_fav_player}}} != blank %} {{custom_attribute.${baseball_fav_player}}}を見たあなたへ — {{custom_attribute.${baseball_fav_team}}}観戦ツアー特集 {% else %} 海外野球の観戦ツアーをまとめてチェック {% endif %}
✔ 動作確認
  • 野球LPを開くと、下部にバナーが表示され、×で閉じられる。
  • CTA クリックで野球LPへ遷移し、URL に utm_medium=inapp が付く。
  • Braze の Campaign 画面で impression / click が計上される。

ここまでで「最小構成」が完成

STEP 0＋1 だけで「Braze から野球LP導線を表示 → 送客」が動く。まずはここを dev で通してから、下の STEP で精度を上げる。

2野球意図イベント・属性を送る（出し分けの土台）ふつう
ゴール：「野球LPを見た人」を Braze のカスタムイベント／属性として記録し、STEP 1 のバナーを野球意図がある人だけに出し分けられるようにする。
手順
  1. GTM にカスタムHTMLタグをもう1つ作る（イベント送信用）。
  2. SDK 初期化（STEP 0）の後に発火させる（タグの順序：STEP 0 タグ → このタグ）。
  3. トリガーは STEP 0 と同じ野球LPパス限定のページビュー。
  4. 公開後、Braze で Segment「baseball_intent = true」を作り、STEP 1 の Target に適用。
GTM カスタムHTMLタグ（野球LP表示で発火）
<script> // 野球カテゴリ/LP を見た＝野球意図シグナル braze.logCustomEvent('baseball_category_view', { area: 'mlb', page: 'baseball-lp' }); var u = braze.getUser(); u.setCustomUserAttribute('baseball_intent', true); u.setCustomUserAttribute('baseball_last_viewed_at', new Date().toISOString()); braze.requestImmediateDataFlush(); // 即時送信（バッチを待たない） </script>
Braze 側のセグメント条件
条件意味
baseball_intent is true野球意図がある
AND baseball_last_viewed_at after time - 14 days直近14日以内（鮮度）
AND baseball_ac_purchased is false購入済みを除外（属性があれば）
球団・選手を取って文面パーソナライズしたい場合

LP内で球団フィルタや選手検索が使われた時に、その値を属性として追加で送る。ページ側でクリック値が取れる場所（フィルタUI等）に紐づける。

u.setCustomUserAttribute('baseball_fav_team', 'dodgers'); u.setCustomUserAttribute('baseball_fav_player', 'ohtani'); u.setCustomUserAttribute('baseball_viewed_area', 'los-angeles'); braze.requestImmediateDataFlush();
✔ 動作確認
  • Braze ＞ 該当ユーザープロフィールで Custom Event baseball_category_view と 属性 baseball_intent=true が記録される。
  • 作ったセグメントの member 数が増える。
  • STEP 1 の Target をこのセグメントに変えると、野球LPを見た人だけにバナーが出る。
3Content Cards（おすすめ枠に1枚常設）ふつう
ゴール：TOP／マイページのおすすめフィードに、閉じても消えない永続カードで野球LP導線を出す。後日戻ってきた再訪 Traveler に効く。フィード描画のフロント実装が必要。
手順
  1. Braze ＞ Content Cards を作成。Key-Value に category = baseball_lp と deeplink（野球LP URL）を設定。
  2. Target を STEP 2 のセグメント（baseball_intent = true）に。
  3. フロントで Content Cards を購読し、野球LP用カードだけを既存フィードに差し込む（下コード）。
フロント：おすすめフィードへ差し込み
braze.subscribeToContentCardsUpdates(function(cards){ var baseball = cards.filter(function(c){ return c.extras && c.extras.category === 'baseball_lp'; }); renderIntoFeed(baseball); // 既存フィードに1枚だけ差し込む }); braze.requestContentCardsRefresh();

なぜ STEP 1・2 より重いか

In-App は Braze が自動描画するが、Content Cards は「どこに・どう並べるか」をフロントで実装する必要がある。既存フィードの改修が絡むため、開発の関与が必要。

4メール配信（Canvas で後追い）重い
ゴール：野球AC/LP を見て離脱した Traveler・過去購入者へ、サイト外からメールで引き戻す。件名・本文は球団／選手名でパーソナライズ。
手順
  1. 会員識別が前提：STEP 0 の braze.changeUser() でログイン Traveler を external_id と結び付けておく。
  2. Braze ＞ Canvas を作成。エントリーを Custom Event baseball_category_view、Delay 24時間を挟む。
  3. Audience に STEP 2 セグメント＋メール購読オプトイン済みを条件追加。
  4. 件名・本文を Liquid でパーソナライズ、CTA を野球LP（utm_medium=email）に。
件名（Liquid）
{% if {{custom_attribute.${baseball_fav_team}}} != blank %}{{custom_attribute.${baseball_fav_team}}}戦、まだ間に合います{% else %}海外野球の観戦ツアー、今チェック{% endif %}

注意（法令・プライバシー）

メールは購読同意（オプトイン）済みの Traveler にのみ配信。頻度上限（例：週1）を設定し、PII は Braze 内で管理して URL には載せない。

5Connected Content（レコメンドAPI＋日次バッチ）最重量
ゴール：メール・レコメンド枠に、配信時に最新の野球AC上位3件を差し込む。在庫・価格が動いても常に最新。Veltra 側のバックエンド構築が必要なため最後。
やること（開発）
  1. 推薦エンドポイントを用意：external_id と area を受け取り、野球AC上位3件を返す（認証付き）。
  2. 日次バッチを用意：GA4 BigQuery export（analytics_347074845.events_*）＋ AC マスターを集計し、購入履歴などの重い属性を Braze REST /users/track に流す。Cloud Scheduler（05:00 JST）→ Cloud Functions。
  3. Braze メッセージ本文で Connected Content を呼び、返り値をループ描画。失敗時のフォールバックを用意。
Braze 本文（Liquid：送信時に推薦APIを取得）
{% connected_content https://api.veltra.com/reco/baseball?external_id={{${user_id}}}&area={{custom_attribute.${baseball_viewed_area}}} :basic_auth reco_secret :save reco %} {% if reco.items != blank %} {% for ac in reco.items limit:3 %} ・{{ac.title}}（{{ac.price}}）→ {{ac.url}} {% endfor %} {% else %} ・人気の海外野球 観戦ツアーを見る → {% endif %}

セキュリティ

推薦APIは認証必須。reco_secret は Braze の Connected Content 認証設定に登録（本文に生の認証情報を書かない）。REST API Key は Secret Manager 管理、BigQuery アクセスは最小権限（Data Viewer）。バッチの成否は Slack へ通知。

※ 詳細な属性スキーマ・SQL・投入コード・稼働責任は設計提案の「共通基盤」節を参照。
