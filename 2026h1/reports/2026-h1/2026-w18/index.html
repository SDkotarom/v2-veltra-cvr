  • WAF は 4/17 適用済（AWS Singapore サブネット 3.172.106.64/26, 3.172.18.128/26 をブロック）— 方向は正しかった
  • ピーク比 -71% に bot を抑え込めたが、正常 baseline（W15 27,270/週）の 4.1 倍（112,554/週）が残存している
  • 同じ AWS IP プールから別 IP・UA ローテーション・Chromium Headless で再来し続けている
  • つまり W18 は 「WAF 適用済だが実態としては bot 影響が継続していた週」であり、当初の「Direct CVR 0.59% は通常水準」評価は希釈後の見かけの数字

01Conclusion — 結論 （当初執筆、上記追記で補正）
W18 / GW週・サイト障害から完全復帰

W18 の数字は「W17 障害日が剥がれ落ちた素直な反動」と「GW 連休の構造変化」が同時に起きており、3 軸で読み解く: (1) 障害復旧の確認（4/26 にすでに 1.22% へ復帰したのが W18 全体で定着、4/29 昭和の日に CVR 1.53% で年初来トップ級）、 (2) 連休 ①→② の希薄化（GW で「とりあえず見てみる」流入が増えたが AC ページまで辿り着く前に離脱、Direct 大幅増・Organic Search 横ばい）、 (3) 構造ボトルネックは W17 と同じ顔ぶれ（BN1 新規 ④→⑤、BN2 モバイル ①→②、BN3 リピーター ①→②… W17 と Top3 順序まで一致）。

復旧の素直な戻り + GW 連休型の流入希薄化 + 構造課題の継続 — 3 つを切り分けて読む

W18 のセッション総数は W17 とほぼ同じ（+0.8%）にもかかわらず、AC ページ到達ユーザーが 402K → 355K（-11.7%）と大きく減少。 セッション×チャネル別では Direct が 28日 baseline で 1.275M セッション・全体の 35% と最大シェアになっており、「ブックマーク・直URL でとりあえずトップを覗いた」層が増えた可能性が高い。 一方で Organic Search のセッションは横ばい、Paid Search は微減で、SEO/SEM 経由の検討意欲ユーザーの絶対数は変わっていない。 GW 中の「見るだけ」流入が分母を膨らませ、相対的に①→②の通過率を引き下げた構造。連休後の W19 で Direct シェアが平常時に戻れば数字も自然回復する見込みだが、もし継続するなら Direct 流入の質的変化（再来訪 vs 新規ブックマーク）の追加調査が必要。

E.04 — bot 状況確認（WAF 運用）

~中立
Direct CVR 0.59%（W17 0.73%）— 通常水準内、bot 流入が支配的なら CVR がさらに沈むはず
W18 は Direct セッションが 28日で 1.275M（全体の 35%）と最大シェアだが、Direct CVR は 0.59% と通常レンジ（過去の bot 汚染週は 0.1% 以下）。 WAF ブロックが運用に入った可能性が高いが、確定情報が手元になく、Mayumi さん／インフラチームへ「WAF の Singapore × Chrome × Win ルール適用日」確認を依頼する。 万が一 GW 連休中に再度 bot ピークが来た場合に検知できるよう、日次×チャネル×デバイスのアラート閾値を継続監視。為替変更（4/20 適用）の純効果分離測定もW19で実施予定。
03Action — やるべきこと
復旧確認の一段落 + GW 後半に向けた BN3／BN1 着手 + 連休 Direct 流入の質的検証の 3 本立て
障害は剥がれた。次の優先は「GW 後半に効く Quick Wins」と「構造課題の地道な実装」。連休型の流入変化は来週 W19 でもう一度確認して、構造化する／しないを判断する。
1
CHECK / 緊急 WAF / インフラ運用確認 優先度: 最高
WAF Singapore × Chrome × Windows ルールの運用状況を確認 — GW 後半 5/4〜5/6 に再来防止
W17 までの 4 週連続で観測された AWS ap-southeast-1 / Singapore × Chrome × Windows bot の指紋が、W18 では Direct CVR 0.59% という通常水準にとどまっているため、WAF ブロックが運用に入っている可能性が高い。 ただし確定情報が手元にないので Mayumi さん／インフラチームへ 「WAF ルール適用日・適用範囲・現在のブロック数」を即日確認。 GW 後半（5/4〜5/6）は需要ピークなので、万が一 bot がルールを掻い潜って再来した場合の即応体制を Slack #urgent-issues で合意しておく。
ステップ: ① WAF ルール適用日・現在のブロック数を確認（半日）② Slack #urgent-issues で GW 期間中の bot 再来時のフロー合意（1日）③ 日次×チャネル×デバイスのアラート閾値を kpi.html で継続監視（既存）
2
既存 BN Top3 / Quick Wins UX / フォーム / リピーター動線 優先度: 高
GW 後半に効く BN3（リピーター ①→②）と BN1（新規 ④→⑤）の Quick Wins から先行着手
Top3 ボトルネックは W16 / W17 / W18 の 3 週連続で同じ顔ぶれ。GW 後半（5/4〜5/6）はリピーター層が動く時期なので、まず BN3（リピーター ①→②）の最近見たAC再表示・ウィッシュリストハイライト系 Quick Winsから先行着手。 並行で BN1（新規 ④→⑤）のフォーム引き算系 Quick Wins（必須項目を代表者1名のみ／同行者情報は予約後収集）を MIB 開発チームでスコープ確認。effort=S の施策のみピックアップすれば 1〜2週間で実装可能。
BN3: リピーターが『前回見たAC』を思い出せず、探し疲れで離脱している（リピーター ①→② -28.7pp / 月33万人影響）
BN1: 新規ユーザーが『長いフォーム＋最終価格の不意打ち』で決済直前に諦めている（新規 ④→⑤ -25.8pp / 月61万人影響）
BN2: モバイルで『自分に合うAC』を見つけられず、比較疲れで離脱している（モバイル ①→② -24.9pp / 月50万人影響）
3
継続 / 計測基盤 ①→② 連休型希薄化の検証 / 為替分析 優先度: 中
①→② -4.79pp と Direct シェア 35% を W19 で再確認 + 4/20 為替変更の純効果測定
①→② -4.79pp は 「GW 連休で冷やかし流入が一時的に増えた」と読んだが、W19 で連休が剥がれた後に Direct シェアが平常時（25〜30%）に戻るか／①→② が回復するかを確認。 戻らない場合、Direct 流入の質的変化（再訪ユーザーがブックマークから入っているか／別の bot 系流入か）の追加調査が必要。 並行で、4/20 為替マージン変更（EU 3.9% / TWD・SGD・MYR 0% / 他 2.9%）の純効果を W18 の通貨×エリア別 CVR で切り出し測定（W17 は障害と bot で交絡していたため、W18 が純粋な比較ベース）。
4
継続 / ダッシュボード kpi.html / レポート運用 優先度: 中
kpi.html に「障害日除外」「bot 除外」のトグルを実装、月次確定の運用に落とし込む
W17 サマリーで宣言した「raw / 障害除外 / bot 除外 の 3 本立て」を kpi.html に実装。月次確定タイミング（5月末）で 2026-04 月次の値を「障害除外版」と「raw版」両方で記録する運用に切り替える。 これがあれば、来年同月比較するときに「2026-04 は障害があったから比較対象外」と判断する判断材料が残る。
