New-KPI initiatives — S2/S3/S4

新KPI＝新規ユーザーの「AC到達→検討」率（②→③）。現状 9.0%、同サイトのリピーターは 22.8%。
伸びしろは新規に集中。意向ステージ S2→S3→S4 の順で、各3施策を具体化。

North Star は CVR（相対 +1%、据え置き）。本ページは新KPIの観点で、新規を1段ずつ前へ進める施策を整理したもの。最優先は S2 比較検討層（供給に触れず・サイト内・今夏に間に合う）。施策は薄めないため各ステージ3つに絞り、各ステージの本命に before/after モックを付す。KPI設計の根拠は KPIダッシュボード 参照。

S2 最優先 / 比較検討層

「これと決めきれず比較中」の新規を、空き状況確認まで運ぶ

S2 比較検討層 最優先・今夏 狙う：新規 ②→③ 9.0% → （天井22.8%）
買う気はあるが「これ」を決めかね、平均3.7件のACを4分かけて見比べている。各ACページが行き止まりで比較を助けず、他社タブや離脱へ流れる。比較をサイト内で収束させ「空き状況を見よう」に変える。
S2-1類似・同観光地AC比較ブロック本命
課題ACページが単体で完結し、比較したいTravelerを次のACへ繋げない。比較のための回遊が他社サイトへ漏れる。
施策「空き状況を見る」CTAの手前に 「同じ観光地の人気AC」「この体験を見た人の比較候補」を3〜4枚カルーセル表示。各カードに価格・所要時間・★評価+件数・即予約可バッジを載せ、横比較を1画面で完結させる。
仕組み初期はML不要。「同エリアタグ × 直近予約数 上位」のルールベース（GA4 予約データ ＋ AC マスターのエリア/カテゴリタグ）を月次バッチで生成。第2段で「閲覧共起（この体験を見た人が見た）」へ拡張。

S2-2「決め手」をCTA手前に集約
課題内容は見たが「日程を見る価値がある」と思える決め手が分散し、効いていない。
施策「空き状況を見る」直前に ★評価+件数 / 本日も予約あり / 即予約可 / 無料キャンセル可否 を1ブロックに集約。情報を足すのではなく、散在する情報を1箇所で効かせる。

S2-3「空き状況を見る」CTAの早期・sticky表示
課題カレンダーへの導線が下部・弱く、検討の入口に気づきにくい。
施策モバイルで「空き状況を見る」を下部固定バー化＋上部にも常設。
工数：小・即UI積み重ね（効果は限定的）戦略軸：迷わず買う
S3 次点 / 絞り込み層

「エリア・やりたいことは決まったが、具体ACが未定」の新規を候補に当てる

S3 絞り込み層 狙う：新規 ①→② 46.8% → （天井68%）
方向は決まっているが具体ACを選べていない。検索はAC閲覧者の1%強しか使われず、エリア/カテゴリ回遊で目的のACに当たれず離脱。探させるより「先回りで当てる」。
S3-1目的別クイック絞り込みチップ ＋ 人気AC Top本命
課題エリア/カテゴリページが網羅的リストで、初訪問のTravelerが「自分向き」を選び切れない。検索は使われない。
施策ページ上部に 目的別チップ（子連れ／初めて／雨でもOK／半日）＋「人気AC Top5」を先回り提示。タップで即絞り込み、具体ACへ最短到達。
仕組みチップ＝AC属性タグのファセット絞り込み。人気Top＝エリア×直近予約数上位（GA4＋ACマスター）。

S3-2検索流入の着地に「やりたいこと」起点ナビ
課題検索流入の着地ページと検索意図がずれ、AC本体に進む前に離脱。
施策着地直後に、検索意図に沿ったやりたいこと別の導線（テーマ別おすすめ）を提示し、合致するACへ誘導。
工数：中戦略軸：取りこぼし防止
S3-3検索・絞り込みの「使われない原因」診断 → 改善
課題検索・絞り込みの利用が極端に低い（AC閲覧者の1%強）。導線が見えない／結果が弱い可能性。
施策まずログ・ヒートマップで未使用の原因を特定してからサジェスト強化／露出改善（診断先行）。
工数：中診断先行
S4 中長期 / 探索層

「今すぐは買わない」新規を、最適なタイミングで連れ戻す

S4 探索層 狙う：新規の再訪率・再訪間隔の短縮
漠然とした興味で来訪し、今は買わない層。離脱後の接点づくりで再訪を早める。お気に入りは現状ほぼ死蔵（採用0.57%・再訪利用699人）。「保存→予約」の相関計測が前提のため、まず計測整備から着手する中長期トラック。
S4-1ワンタップお気に入り ＋ 保存リストからの予約導線本命
課題お気に入りの保存ハードルが高く、保存しても戻って使われない（再訪利用699人）。意向の取りこぼし。
施策ACカード/ページにワンタップ保存。保存後は「保存リスト」から価格・残枠とともに即予約導線。再訪時に保存からスムーズに予約へ。
仕組み保存イベントの拡充＋「保存→予約」相関の計測整備（前提）。相関が確認できれば次のS4-2へ接続。

S4-2保存AC・エリアの価格／残枠変動リマインド（Braze）
課題離脱後の再訪トリガーがなく、最適なタイミングを逃す。
施策保存したACの価格下落・残枠わずかを Braze Content Card／Push で通知し再訪を促す。
仕組みGA4 BigQuery export の保存イベント＋ACマスター（価格・在庫）→ Cloud Scheduler で日次抽出 → Braze へ投入 → Liquid でカード描画。※ データソース／クエリ／属性スキーマ／Liquid 等の詳細Howは実装ドキュメントで全項目記載。
工数：大中長期戦略軸：滞在中プラスアルファ
