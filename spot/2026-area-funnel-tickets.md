# エリアページ改修｜開発チケット集（4件）

> ベルトラ発のおすすめ偏重で探しにくいエリアページを、「自分で探す」を最上部1箇所に集約し、「おすすめ」でACを多彩に並べ、**有効AC到達率**を上げる。
> 各チケットは ClickUp にそのままコピペできる Markdown。1チケット＝1見出し（`## T-xx`）でコピーしてください。

## エピック概要（共通前提・全チケットに適用）

| 項目 | 内容 |
|---|---|
| 対象画面 | エリアページ（Site: JP / Device: Mobile・PC、SP優先設計） |
| 狙う層 | **③ 方向だけ**（エリア等の方向はあるが具体ACは未定） |
| Primary KPI | **有効AC到達率**＝エリアページ流入セッションのうち、AC（商品）ページへ到達し、かつ即離脱しないセッションの比率 |
| 戦略軸 | メインスポット取りこぼし防止 |
| 出典 | GA4 Property `347074845`（日本・28日・bot除外、2026-05-11〜06-07） |
| 関連分析 | 探索分解と施策 `/spot/2026-ac-discovery.html`／改修ワイヤー `/spot/2026-surface-wireframes.html` |

**現状の根拠（なぜエリアページか）**
- エントリー別CVR(session)＝GlobalTOP 2.28% ＞ **エリア 1.21%** ＞ カテゴリ 1.07%。改修着手はファネル上流のCVR順。
- エリアページは ③方向だけ層の主戦場。新規の「AC到達→検討」は 9.0%（リピーター 22.8%）で最大ギャップ。
- 既存のエリアページは「ベルトラ発のおすすめ（売れ筋固定ランキング＋人気カテゴリ）」が中心で、Traveler が自分の軸（種別・日付・キーワード）で能動的に探す入口が散在し、AC（商品）そのものに辿り着く前に離脱している。

**方針＝エリアページを3ゾーンに再構成**
1. **① 自分で探す**（最上部・1箇所に集約／遷移型）＝ T-SEARCH ＋ T-A5
2. **② エリアのおすすめ**（ACを積む／インライン型・1タップでAC到達）＝ T-A3 ＋ T-A7
3. **③ 索引・計画情報**（観光地TOP20・エリアから探す 等＝既存・本スコープ外）

**4チケットと推奨着手順**

| 順 | チケット | ゾーン | 表示形式 | 開発規模の目安 | 主な根拠 |
|---|---|---|---|---|---|
| 1 | **T-A5** ジャンルから探す（常時ボタン） | ①自分で探す | 遷移型 | 小 | 既存カテゴリ体系を流用し新規開発がほぼ不要のクイックウィン |
| 2 | **T-A3** ランキング切り口タブ | ②おすすめ | インライン | 中 | 共通3切り口は既存データで成立、その場のタップ＝AC到達でKPI直結 |
| 3 | **T-A7** ジャンル別おすすめ | ②おすすめ | インライン | 中 | 既存カテゴリ分類・既存並びを流用、エリアの多彩さを見せて回遊増 |
| 4 | **T-SEARCH** 探す検索ユニット | ①自分で探す | 遷移型 | 大 | サジェスト・検索実需データ・日付在庫統合で作り込みが必要 |

**共通テスト設計**
- Control＝現行エリアページ（当該モジュール無し）／ Variant＝当該モジュール追加版
- 対象エリアはトラフィックとデータが充足するエリアから段階展開（具体エリアは関係者で確定＝相談ポイント）
- Site: JP／Device: Mobile・PC

**共通ガードレール**
- エリアページ直帰率（悪化させない）
- エリアページ CVR(session)（1.21%を下回らせない）
- 既存導線（人気カテゴリ・あなたにおすすめ・グローバルナビ）のCTR（カニバリゼーション監視）

**共通セキュリティ／運用前提**
- 月次の選定バッチ（並び順・タブ出し分け）のデータ参照は最小権限の読み取りに限定。
- 認証情報・APIキーはハードコードせず、シークレット管理（環境変数／Secret Manager等）で扱う。
- 計測イベントに個人を特定できる値（メール・氏名等）を載せない。

**関係者（共通・RACIの目安）**
- PdM：スコープ／優先順位／リリース判断（Accountable）
- UXデザイン：SPワイヤー→デザイン、薄いタブ・常時ボタンの実装仕様
- フロントエンド：UI実装、計測イベント実装
- データ／アナリティクス(GA4)：A/B設計、有効AC到達率の定義確定、イベント設計レビュー
- 検索／在庫バックエンド：検索サジェスト、サイト内検索データ、日付・在庫（主に T-SEARCH）
- マーケ／カテゴリ運用：ジャンル・ランキングの月次選定運用の確認
- CRM(Braze)：先行プローブや人気スポット静的カードを使う場合のみ（任意）

## T-A5 ジャンルから探す（常時ボタン・KKday型）

### 概要 / Overview
エリアページの「探す」直下に、種別（観光ツアー・アクティビティ・チケット・交通・グルメ 等）のアイコンボタンを 5〜7 個**常時表示**し、Traveler が種別起点で能動的に探せる入口を作る。タブの中に隠さず、エリア×ジャンルの既存一覧へ送る。

### 狙う層・KPI・戦略軸
- 層：③ 方向だけ
- Primary KPI：有効AC到達率
- 戦略軸：メインスポット取りこぼし防止

### 仮説 / Hypothesis
- **課題**：種別（観光ツアー・交通・チケット 等）起点で探したい Traveler の入口が無い。絞り込みがタブやモーダルの中に隠れると気づかれず、受け身でランキングを眺めて離脱する。
- **打ち手**：探すユニットの直下に 5〜7 個のジャンルボタンを常時表示し、1タップでエリア×ジャンル一覧へ送る。
- **期待成果**：能動的な探索が増え、一覧→AC到達が伸び、有効AC到達率が上がる。

### ユーザーストーリー & 受け入れ条件
**ユーザーストーリー**
- As a Traveler、エリアページを開いたとき、まず「どんな種類の体験があるか」を一目で選びたい。so that 自分の関心（チケットだけ／交通だけ 等）に最短で辿り着ける。

**受け入れ条件（Given-When-Then）**
- [ ] Given エリアページを表示、When ファーストビュー付近を見る、Then 探すユニット直下にジャンルボタンが 5〜7 個、常時（タブ展開不要で）表示されている。
- [ ] Given ジャンルボタンを1つタップ、When 遷移、Then そのエリア×ジャンルの既存一覧ページが開く（新規画面を作らない）。
- [ ] Given エリアごとに需要構成が違う、When ページを表示、Then 並び順がそのエリアの需要の大きい順になっている。
- [ ] Given ボタンをタップ、When 計測、Then `genre_btn_click(genre, position)` が発火する。
- [ ] SP（390px幅）で横スクロールや崩れが無い。

### 詳細仕様
- **配置**：探すユニット（T-SEARCH）の直下。タブに隠さず常時表示。アイコン＋ラベルのボタンを 5〜7 個。
- **ジャンル種別**：既存グローバルナビのカテゴリ体系を流用（例：観光ツアー／アクティビティ／チケット／交通・移動／グルメ／eSIM・WiFi）。
- **並び順ロジック**：エリアごとに需要の大きい順。リゾート系はアクティビティ・チケットが上位、都市系はグルメ・交通が上位 等。**月次バッチ**で予約実績（DWH/BigQuery）を集計し、エリア別のジャンル並び順データを生成してフロントが参照する。
- **着地**：エリア×ジャンルの既存一覧ページ（新規開発なし）。
- **不採用（明記）**：「条件でしぼる（A-4）」はこの画面では採用しない。エリア×条件だけでは検索範囲が広く需要が薄いため、ジャンル×条件の絞り込みはカテゴリページ（C-1 ファセット／C-4 人気の絞り込み）で実施する。

### テストパターン / Test Variations
- **Control**：現行エリアページ（ジャンル常時ボタン無し）。
- **Variant**：探す直下にジャンル常時ボタンを表示。
- Site: JP／Device: Mobile・PC。

### 指標 / Metrics
- **Primary**：有効AC到達率
- **Sub**：ジャンルボタンCTR（`genre_btn_click`率）／エリア×ジャンル一覧への到達率／一覧→AC到達率
- **Guardrail**：エリアページ直帰率／CVR(session)／既存カテゴリ・グローバルナビ動線のCTR（カニバリ監視）

### 計測イベント
- `genre_btn_click(genre, position)`

### スコープ・依存
- **新規開発はほぼ無し**：既存カテゴリ体系・既存一覧ページを流用。
- 月次のジャンル並び順選定バッチ（予約実績の集計）。
- 計測基盤（イベント実装）に依存。

### 関係者・相談ポイント
- 主担当：フロントエンド／マーケ・カテゴリ運用（並び順）／データ(GA4)（計測）
- 相談ポイント：
  - [ ] 常時表示するジャンルの**個数（5 or 6 or 7）**とエリア横断の初期セット
  - [ ] 並び順の月次更新の**データソースと運用責任**の確定
  - [ ] 1行カルーセル表示にするか、折り返しグリッドにするか（SPの占有面積）

### 参照
- 改修ワイヤー：`/spot/2026-surface-wireframes.html#wf-area`（A-5）
- 探索分解：`/spot/2026-ac-discovery.html`（③ 方向だけ）

## T-A3 ランキング切り口タブ（共通3＋エリア可変N）

### 概要 / Overview
おすすめゾーン先頭の「ランキング」を、固定の売れ筋一本から**切り口タブ**に拡張する。全エリア共通3切り口（売れ筋・満足度・急上昇）に、エリアのデータが充足したときだけ可変タブ（子連れ・直前OK・テーマ）を自動追加。各タブはインラインのACカルーセル（10件＋すべて見る）で、その場のタップ＝AC到達。

### 狙う層・KPI・戦略軸
- 層：③ 方向だけ
- Primary KPI：有効AC到達率
- 戦略軸：メインスポット取りこぼし防止

### 仮説 / Hypothesis
- **課題**：ランキングが売れ筋・満足度の固定でいつ見てもほぼ同じ。時期や自分に合うかが分からず素通りされる。
- **打ち手**：切り口タブで複数の見せ方を用意し、時期で動く「急上昇」やエリアに合う可変タブで新候補に出会わせる。
- **期待成果**：ランキングCTRと Top外（4位以降）のAC到達比率が上がり、有効AC到達率が上がる。

### ユーザーストーリー & 受け入れ条件
**ユーザーストーリー**
- As a Traveler、エリアのおすすめを見るとき、売れ筋以外の切り口（評価が高い・いま伸びている・自分の条件に合う）でも見比べたい。so that 定番以外の自分に合うACに出会える。

**受け入れ条件（Given-When-Then）**
- [ ] Given エリアページのおすすめゾーン、When 先頭を見る、Then 共通3タブ（売れ筋／満足度／急上昇）が表示され、初期は売れ筋。
- [ ] Given 各タブ、When 表示、Then タブ直下にキャッチ1行（売れ筋「いちばん予約されています」等）が出る。
- [ ] Given タブをタップ、When 切替、Then そのタブのACカルーセル（最大10件＋すべて見る）が即時に切り替わる。
- [ ] Given エリアのデータが充足、When 表示、Then 該当エリアにだけ可変タブ（子連れ／直前OK／テーマ）が自動追加される。データ不足エリアでは表示されない。
- [ ] Given ACカードをタップ、When 遷移、Then AC詳細へ到達（その場のタップ＝AC到達）。
- [ ] Given タブ切替、When 計測、Then `ranking_tab_switch(tab)` が発火する。

### 詳細仕様
- **配置**：おすすめゾーン先頭（ファーストビュー近く）。
- **表示形式**：インライン（ACカルーセル 10件＋すべて見る）。タップ＝AC到達。
- **共通3切り口（全エリア）**

  | 切り口 | キャッチ | データ |
  |---|---|---|
  | 売れ筋 | いちばん予約されています | 直近30日の予約数（既存） |
  | 満足度 | クチコミ評価が高い順 | 体験談の評価（既存） |
  | 急上昇 | 予約が急に伸びています | 予約数の前週/前月比の伸長（季節ものを拾う） |

- **可変切り口（エリア可変・データ充足時のみ自動表示）**

  | 切り口 | キャッチ | 出す条件 |
  |---|---|---|
  | 子連れに人気 | お子さま連れに人気 | 家族予約比率・体験談「子ども」言及が一定以上のエリアのみ |
  | 直前でも取れる | 今日・明日に参加できる | 当日〜翌日在庫があるACが一定数あるエリアのみ |
  | テーマ（海/自然/文化…） | — | そのエリアの主力テーマに応じて1〜2本 |

- **出し分けロジック**：共通3＋可変N。可変タブは**月次バッチ**でエリアごとのデータ充足を判定して自動で出し入れ（固定で全部出さない）。データソースは予約実績・体験談・在庫（DWH/BigQuery＋在庫データ）。
- **考察**：売れ筋・満足度・急上昇は「実績データ×普遍的な切り口」でどのエリアでも成立。子連れ・直前OK・テーマはエリアの在庫構成や客層に依存するため、合わないエリアでは0件や的外れになる。データ充足を条件に自動で出し分ける。

### テストパターン / Test Variations
- **Control**：現行の固定ランキング（売れ筋中心）。
- **Variant**：切り口タブ（共通3＋可変N）。
- （任意の追加アーム）可変タブ有無の比較。
- Site: JP／Device: Mobile・PC。

### 指標 / Metrics
- **Primary**：有効AC到達率
- **Sub**：ランキングCTR／Top外（4位以降）AC到達比率／`ranking_tab_switch`率・タブ別CTR
- **Guardrail**：直帰率／CVR(session)／可変タブの誤表示（データ不足エリアに出ていないか）

### 計測イベント
- `ranking_tab_switch(tab)`
- （カード）AC到達イベントにランキング経由・タブ・順位の文脈を付与

### スコープ・依存
- 共通3タブは既存データで成立。
- 可変タブはデータ充足判定バッチ（月次）。
- インラインACカルーセルUIの新規実装（T-A7とUI共通化可）。
- ランキング算出（DWH/定期ジョブ）・計測に依存。

### 関係者・相談ポイント
- 主担当：フロントエンド／データ(GA4)・分析（算出・判定）／PdM
- 相談ポイント：
  - [ ] 「急上昇」の**算出窓と閾値**（前週比か前月比か、最低予約数の足切り）
  - [ ] 可変タブを出す**データ充足の閾値**（家族予約比率○%・直前在庫○件 等）
  - [ ] カルーセル件数（10件で確定か）と「すべて見る」の着地
  - [ ] 有効AC到達率の「即離脱しない」の定義（滞在秒数・スクロール・2ページ目 等）

### 参照
- 改修ワイヤー：`/spot/2026-surface-wireframes.html#wf-area`（A-3）

## T-A7 ジャンル別おすすめ（カテゴリ別の人気AC行）

### 概要 / Overview
おすすめゾーンに、カテゴリごとの人気ACを**横1列×複数行**で積む（半日・1日ツアー／チケット／交通／グルメ…）。各行右に「すべて見る」。ランキングや単一おすすめだけでは見えないエリアの多彩さを、実ACカードで見せて回遊とAC到達を増やす。

### 狙う層・KPI・戦略軸
- 層：③ 方向だけ
- Primary KPI：有効AC到達率
- 戦略軸：メインスポット取りこぼし防止

### 仮説 / Hypothesis
- **課題**：ランキング／単一のおすすめだけだと、自分の興味カテゴリのACに辿り着きにくく、エリアの多彩さ（チケット・交通・グルメ 等の幅）が見えない。
- **打ち手**：カテゴリ別に人気ACを横1列ずつ複数行で積み、興味カテゴリの行で実ACに直接出会わせる。
- **期待成果**：おすすめ経由のAC到達と、行間の横移動（回遊）が増える。

### ユーザーストーリー & 受け入れ条件
**ユーザーストーリー**
- As a Traveler、エリアのおすすめを見るとき、種類ごと（ツアー・チケット・交通…）に実際のACを数件ずつ眺めたい。so that 1本のランキングに縛られず、自分の興味カテゴリのACにそのまま出会える。

**受け入れ条件（Given-When-Then）**
- [ ] Given エリアページのおすすめゾーン、When 表示、Then カテゴリごとに横1列（3〜5件）＋「すべて見る」が複数行で積まれている。
- [ ] Given 行（ジャンル）の選定、When 表示、Then そのエリアで予約が多いカテゴリ順の上位（在庫AC5件以上のカテゴリのみ）が並ぶ。
- [ ] Given 各行のAC、When 表示、Then そのカテゴリの既存の並び順（売れ筋）上位5件がそのまま使われる（新規の並び替えをしない）。
- [ ] Given ACカードをタップ、When 遷移、Then AC詳細へ到達。
- [ ] Given 「すべて見る」をタップ、When 遷移、Then そのカテゴリ一覧へ。
- [ ] Given カード/すべて見るをタップ、When 計測、Then `genre_row_card_click(category_id, position)`／`genre_row_seeall_click(category_id)` が発火する。

### 詳細仕様
- **配置**：おすすめゾーン（人気カテゴリ・あなたにおすすめの近傍）。
- **表示形式**：インライン（カテゴリ別ロー×複数）。
- **束ねる軸**：既存のカテゴリ分類をそのまま流用（新規タグ付け不要）。
- **行（ジャンル）の選定**：そのエリアで予約が多いカテゴリ順の**上位6**（在庫AC≥5のカテゴリのみ・**月次更新**）。リゾートと都市で並ぶカテゴリが変わる。
- **各行のAC**：そのカテゴリの既存の並び順（売れ筋）**上位5件**をそのまま使用（新規の並び替えロジック不要）。
- **データ生成**：月次バッチで予約実績（DWH/BigQuery）からエリア×カテゴリの予約ランクを算出し、行構成データを生成してフロントが参照。

### テストパターン / Test Variations
- **Control**：現行（ジャンル別おすすめ行なし）。
- **Variant**：カテゴリ別の人気AC行を複数表示。
- （任意）行数（例：3行 vs 6行）の比較で情報過多を検証。
- Site: JP／Device: Mobile・PC。

### 指標 / Metrics
- **Primary**：有効AC到達率
- **Sub**：おすすめ経由のAC到達数／回遊（複数ジャンル行の閲覧率・行間横移動）／`genre_row_card_click`・`genre_row_seeall_click`率
- **Guardrail**：直帰率／CVR(session)／ページ高さ増による下部既存モジュールのスクロール到達・視認低下

### 計測イベント
- `genre_row_card_click(category_id, position)`
- `genre_row_seeall_click(category_id)`

### スコープ・依存

## T-SEARCH 探す検索ユニット（A-8 サジェスト＋A-2 人気検索ワード＋A-6 日付・いますぐ）

### 概要 / Overview
エリアページ最上部に「自分で探す」を1箇所に集約する薄いタブ（常に1タブ分だけ表示）。タブ1＝行き先・キーワード（タップで検索サジェスト＝検索履歴／人気の検索ワード／人気スポット を展開）、タブ2＝日付・いますぐ（このエリア固定で 今日・明日・日付指定）。空欄でも候補が出て、日付・直前ニーズの入口も用意する。

### 狙う層・KPI・戦略軸
- 層：③ 方向だけ（＋直前型を一部回収）
- Primary KPI：有効AC到達率
- 戦略軸：メインスポット取りこぼし防止

### 仮説 / Hypothesis
- **課題**：検索窓は入力前提で、空欄のままだと何も起きず素通りされる。何で検索すればいいか分からない人が離脱する。日付・現地ですぐ参加したい直前ニーズの入口が無い／埋もれる。
- **打ち手**：検索窓タップでサジェスト（履歴・人気ワード・人気スポット）を展開し、空欄でも1タップで結果へ。日付・いますぐタブで直前ニーズの入口を最上部に置く。
- **期待成果**：検索開始（現状6.6%・モバイル7.1%）の裾野を回収し、検索・日付経由のAC到達が増え、有効AC到達率が上がる。

### ユーザーストーリー & 受け入れ条件
**ユーザーストーリー**
- As a Traveler、エリアページで検索窓に触れたとき、何を入れればいいか分からなくても候補（よく探される言葉・人気スポット・過去の検索）を見たい。so that 入力に迷わず1タップで一覧へ進める。
- As a Traveler（現地・直前）、今日・明日に参加できるものを最上部からすぐ探したい。so that 滞在中の直前ニーズで取りこぼされない。

**受け入れ条件（Given-When-Then）**
- [ ] Given エリアページ最上部、When 表示、Then 薄いタブ（行き先・キーワード／日付・いますぐ）が常に1タブ分だけ表示され、画面を占有しない。
- [ ] Given 行き先・キーワードタブ、When 検索窓をタップ、Then サジェストが展開：①検索履歴 ②人気の検索ワード ③人気スポット。
- [ ] Given 人気の検索ワード、When 表示、Then エリア×直近90日のサイト内検索 上位5語が出る（スポット名は人気スポット側に任せ、ここは体験・条件語に限定）。
- [ ] Given サジェストの項目をタップ、When 遷移、Then エリア絞込済のサイト内検索結果へ。
- [ ] Given 日付・いますぐタブ、When 表示、Then このエリア固定で 今日・明日・日付指定が選べる（エリア変更は無し）。
- [ ] Given 日付を選ぶ、When 遷移、Then 既存の日付フィルタ付き一覧へ（新規画面なし）。
- [ ] Given 各操作、When 計測、Then `find_tab_switch`／`search_focus_open`／`suggest_chip_click(type/keyword)`／`date_search_submit` が発火する。

### 詳細仕様
- **構成**：薄いタブ（常に1タブ分だけ表示・遷移型）。タブ1＝行き先・キーワード（初期表示）、タブ2＝日付・いますぐ。
- **A-8 検索サジェスト（検索窓タップ時）**：検索窓タップでサジェストを展開。①検索履歴（端末保持）②人気の検索ワード（A-2）③人気スポット（既存の人気カテゴリ由来）。本文の他ブロックと重複してよい（Klook/KKday型）。
- **A-2 人気の検索ワード**：検索サジェスト内に表示。データ＝エリア×直近90日のサイト内検索 上位5語（季節性×安定性の折衷・**月次**）。リンク先＝サイト内検索結果（エリア絞込済）。スポット名は人気スポットに任せ、ここは体験・条件語に限定。
- **A-6 日付・いますぐ**：このエリア固定で 今日・明日・日付指定。着地＝既存の日付フィルタ（today/tomorrow/指定）。新規画面なし。件数は当日〜翌日在庫から算出。
- **不採用（明記）**：「条件でしぼる（A-4）」はこの画面では採用しない（→ カテゴリ C-1／C-4）。
- **設計考察（A-2）**：既存軸の昇格（子供と・半日で）は「条件」と語彙が重複し価値が薄い。検索実需チップを採るのは、①Traveler の言葉（「天国の海」等はベルトラ分類に無い）②実需準拠で当たりやすい ③時期で自動入替 ④検索開始の入力負荷を肩代わり できるため。検索ボックスの隣に置くのが要点。

### テストパターン / Test Variations
- **Control**：現行の検索（入力前提・サジェスト無し／日付・いますぐの前面入口無し）。
- **Variant**：薄いタブ＋検索サジェスト＋日付・いますぐ。
- （任意のアーム）タブ方式 vs 検索窓タップでモーダル方式（相談ポイント参照）。
