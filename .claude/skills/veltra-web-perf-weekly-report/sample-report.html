2分かったことWhat we learned

01

立ち上がりではなく、半年かけて悪化しているThis is a six-month slide, not a launch dip

エリアは3/28 の 1,660ms が最速で、そこから 8/29 の 2,714ms まで +1,054ms 悪化した。3月時点では合格していたページが、いま要改善に落ちている。TOP も同期間で 2,514 → 2,805ms。放置すると戻らない種類の劣化で、原因の特定が要る。Area was fastest at 1,660ms on Mar 28 and has since degraded by +1,054ms to 2,714ms on Aug 29. A page that passed in March now needs work. TOP moved 2,514 → 2,805ms over the same period. This kind of drift does not reverse on its own — the cause has to be found.

02

検索結果の遅さは、フロントでは直せないSearch cannot be fixed on the front end

LCP 6,708ms のうち TTFB が 4,851ms（72%）。画像最適化も preload も、残り 1,857ms の中でしか効かない。目標 2,500ms に対してサーバー応答だけで倍近く超えている。このページだけは別の打ち手が要る。Of the 6,708ms LCP, TTFB accounts for 4,851ms (72%). Image work and preload can only operate inside the remaining 1,857ms. Server response alone is nearly double the 2,500ms target. This page needs a different lever.

03

4月中旬に、検索結果で何かが起きたSomething happened to Search in mid-April

4/11 の 3,179ms から 4/18 に 6,148ms へ跳ね、5/16 には 9,392ms まで悪化した。同時期に CLS も 0 から 0.44 へ。これは推定だが、単調な劣化ではなく特定の変更が引き金になった動きに見える。当時のリリース内容を当たれば原因が分かる可能性がある。It jumped from 3,179ms on Apr 11 to 6,148ms on Apr 18, reaching 9,392ms by May 16. CLS moved from 0 to 0.44 over the same weeks. This is an inference, but the shape looks like a specific change rather than gradual drift. Checking what shipped around then may identify it.

04

AC詳細は、そもそも測れていないAC detail is not being measured at all

6月下旬以降、CrUX から URL 単位のデータが返っていない。アクセス数が掲載閾値に届かないため。KPI の分母が1ページ欠けた状態で、施策の効果も判定できない。CrUX has returned no URL-level data since late June because traffic falls below the reporting threshold. One page is missing from the KPI denominator, so improvements there cannot be verified.
