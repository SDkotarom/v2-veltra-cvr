スポーツナビゲーションページ｜プロジェクト計画

スポーツナビゲーションページ新設に関する相談（2026-04-21）を踏まえ、モック作成前にプロジェクトの「なぜ・どう作るか・期待効果・運用ルール」を整理する。本ドキュメントの方針合意をもって、モック作成・PRD起票に進む。

Executive Summary（結論先出し）

エリアに分散するスポーツ観戦商品を 「スポーツ × 種目」軸のテーマハブ として束ねるページ群を新設する。/theme/sports/ 配下の独立軸で第1弾リリースし、効果検証後にグロカテ統合を検討。

何がわかったか

  • スポーツ観戦商品は「行先 → 体験」の現行導線で取りこぼされている
  • worldsports-c.com型のスポーツハブはVeltraに存在せず、SEOで露出できていない
  • 戦略3軸の「メインスポット取りこぼし防止」に直結する目的型商材
  • 類似ニーズ（ショー・高速バス）が今後発生する見込みあり、テンプレ化の価値高い

何をすべきか

  • 独立URL /theme/sports/ 配下にハブ構造を新設
  • テーマページは「絞り込む場」に役割を純化、予約は既存acに委譲
  • テーマページ量産の4ゲート（後述）を運用ルール化
  • 第1弾はサッカー1種目で効果検証 → 他種目・他テーマへ展開

01背景：なぜスポーツナビが必要か

相談で提起された問題を構造化すると、課題は3層に分かれる。

課題 1
商品がエリアに分散

FCバルセロナ → スペイン/バルセロナ、アーセナル → 英国/ロンドン。サッカーで横断比較ができない。

課題 2
SEOで露出しない

「サッカー観戦 海外」「NBA チケット」等の指名検索に対し、束ねるページが無く順位を取れない。

課題 3
ファン動機に届かない

既存導線は「行先 → 体験」。Travelerが「特定スポーツのファン」として探す動線（試合 → 行先）と逆。

戦略3軸との接続（上長確認済・5/11メモ）

軸 1
メインスポット取りこぼし防止 ✓
スポーツ観戦は旅行のメイン目的になりやすい目的型商材。短期化トレンドにマッチ。
軸 2
迷わず買ってもらう
テーマページの「役割純化」によって間接的に寄与（情報の引き算原則）。
軸 3
滞在中プラスアルファ
本施策の直接スコープ外。スポーツacの関連商品レコメンドで別途扱う。

対象カテゴリ（相談メモから）

カテゴリ想定種目・内容優先度
スポーツサッカー / 野球 / バスケ / ホッケー / テニス / ラグビー / モタスポ第1弾
ショーミュージカル / シルク / オペラ第2弾

03サイトマップ案

スポーツを「エリアと並ぶテーマ軸」として独立させる構造。URL設計とグロカテとの関係を明示。

URL階層（第1弾）

/jp/theme/sports/ — スポーツTOP
├─ /jp/theme/sports/soccer/ — サッカー（第1弾着手）
├─ /jp/theme/sports/baseball/ — 野球（MLB）
├─ /jp/theme/sports/basketball/ — バスケ（NBA）
├─ /jp/theme/sports/ice_hockey/ — アイスホッケー（NHL）
├─ /jp/theme/sports/tennis/ — テニス（4大大会）
├─ /jp/theme/sports/rugby/ — ラグビー
└─ /jp/theme/sports/motorsports/ — モタスポ（F1等）
/jp/theme/show/ — ショー（第2弾・テンプレ流用）
/jp/theme/transport/highway_bus/ — 高速バス（第3弾・テンプレ流用）

URL設計のポイント

/theme/ プレフィックスエリア構造（/jp/europe/...）と完全に独立。将来「ショー」「移動手段」も同パターンで増やせる。
英語スラッグ既存URL慣習に合わせる（/europe/, /asia/ 等と統一）。
既存acはそのまま予約は既存 a/17513 等で完結。テーマページはリンクハブに徹する（重複ページ問題を回避）。
canonical設定商品はacページをcanonicalとし、テーマページからは内部リンクで集約する。

ページ役割の定義（CVR戦略 Section 3 準拠）

ページ役割出す情報出さない情報
スポーツTOP種目の入口を一望種目カード、人気観戦地、シーズンカレンダー個別チームの試合詳細、価格比較
種目別ページリーグ・チーム・大会を絞り込むリーグ概要、チーム一覧、観戦Acカード、スケジュールプラン詳細、座席詳細、決済情報

グロカテとの関係

論点: 4/21メモで未決の「グロカテ使える？」について。結論案: 第1弾は別軸として独立リリース。理由は、グロカテ階層に組み込むと既存「カテゴリ × エリア」構造の変更範囲が大きく、初期コストが膨らむため。 /theme/ 配下で独立公開し、効果検証後にグロカテ統合を判断する。
※ この判断はエンジニア合意が必要 → 論点表（Section 06）に記載。

04効果仮説

「なぜこの構造で作るのか」を、SEO・UX・CVRの3視点で言語化する。施策判断と効果測定の根拠になる。

SEO

狙うクエリ「サッカー観戦 海外」「MLB 観戦 ツアー」「ウィンブルドン チケット」「F1 観戦 ツアー」など、種目・大会名での検索

仮説現状これらクエリでVeltraは個別ac（深い階層）でしか露出していない。種目ハブを作ることで、内部リンクが集約され順位が上がる

測定Ahrefs で対象キーワード群の順位と検索ボリュームを事前ベースライン化、3ヶ月後にYoY比較

UX

対象「行先未定 × スポーツ目的」のTraveler（例：「夏に海外でサッカー観戦したい、場所は問わない」）

仮説現状の「エリア → カテゴリ」では行先を先に決める必要があり、この層を取り逃がしている

測定テーマページの直帰率、テーマ → ac遷移率、テーマ経由のCVR

CVR

ファネル主に ②回遊（新規流入の入口拡張）

仮説目的型流入はCVRが高い傾向（既存 Direct = 2.98%）。テーマ流入のCVRも平均超えが見込める

測定テーマページ landing セッションのCVRを、エリア landing と比較。3ヶ月で +0.1〜0.3pt の押し上げ寄与を狙う

想定売上見込み（要試算）

相談メモの「売上見込み」項目への試算アプローチ:
  • 既存スポーツ観戦acの月間予約数を基準値とし、SEO流入増分 × 想定CVR で試算
  • スポーツ関連acの月間総セッションを GA4 (property 347074845) から抽出 → 種目別に按分
  • 類似テーマページがあれば、その流入実績から係数を取って予測

05運用ルール

「類似のテーマ括りページを作りたくなることは多そう。運用ルールを考えて欲しい」という依頼への回答。

新テーマページ作成のゲート（4条件すべて満たすこと）

① 既存カテゴリで括れない

エリア・カテゴリのどちらでも代替不可なときのみ新設。代替可能なら既存ページを強化する。

② 月間検索ボリューム閾値

主要クエリの合計が月1万以上（仮置き、チームで閾値合意要）。

③ 商品数の最低ライン

10ac以上、かつ3つ以上のエリアにまたがる（横断する意義が成立する）。

④ メンテ担当者が明確

廃れたページが残るのを防ぐため、コンテンツ更新の担当を最初に決める。

テンプレート構成（テーマTOP / 種目別の共通骨格）

セクション必須/任意運用負荷
ヒーロー＋紹介テキスト必須初回のみ
サブカテゴリカード（種目・チーム）必須追加時のみ
人気Acカード一覧必須自動反映推奨
試合・公演スケジュール任意自動反映推奨
観戦ガイド・基礎知識必須初回のみ
FAQ任意年1回更新

自動反映の仕組み（提案）

方針: 「人気Acカード」と「スケジュール」は ac の構造化データ（JSON）から自動生成する。テーマページごとに tags: [sport, soccer] のような分類タグを ac に付与し、タグマッチで動的に表示する。

初期フェーズ: 手動運用（CSV または管理画面で ac リスト・スケジュール更新）でリリースし、効果検証後に自動化投資を判断するのが現実的（Phase分割の理由: リスク管理）。

原稿作成ガイドライン（必須ルール）

サービス名表記必ず Veltra（VELTRA / VeL·ToA / ベルトラ等の表記揺れ禁止）
主語「Traveler」（本人・ユーザー・お客様は使わない）
他社コピペ禁止チーム名・大会紹介はすべて自作原稿。他社サイトの文章を流用しない
写真・エンブレム使用不可。タイポグラフィ・アイコン・カラー設計でブランド感を出す
最小フォント13px 以上

07タスク・スケジュール

Phase分割の理由: ① 合意形成は意思決定の塊なので独立、② 仕様確定とモックは Phase 1 のアウトプット依存、③ 実装は仕様凍結後に着手で手戻り回避。

Phase 1合意形成〜2週間

  • 本ドキュメントをチームレビュー → 修正
  • ステークホルダー調整（エンジニア、SEO、マーケ、仕入）
  • Ahrefs MCPでキーワード調査と検索ボリューム取得
  • GA4 (property 347074845) で既存スポーツacの月間セッション・予約数を抽出 → 売上見込み試算
  • 競合OTAの最新状況1〜2hブラウジング

Phase 2仕様確定とモック〜3週間

  • 静的モック作成（スポーツTOP + サッカーページ）
  • テンプレートデザイン（Figma） — デザイナー連携
  • 原稿作成ガイドライン作成（表記ルール、文字量基準）
  • PRD作成（PRD template準拠）／ClickUp起票
  • GTMイベント設計（テーマ → ac遷移、テーマ landing CVR）

Phase 3実装とリリース〜2ヶ月

  • 原稿執筆（チーム名・大会紹介、自作で他社コピペ厳禁）
  • フロント実装、GA4イベント実装、QA
  • サッカーから段階リリース
  • リリース後3ヶ月の効果測定 → 他種目展開 or 中止判断
判定ゲート（Phase 3 完了後 3ヶ月）: ① テーマ landing CVR が エリア landing CVR を上回る ② 対象キーワードでの順位が10位以内に1個以上入る ③ 月間テーマ流入セッションが目標値（試算後決定）を超える — のうち2つ以上達成で「他種目展開」を意思決定。未達なら設計見直し。
次の意思決定ポイント（本MTGで合意したいこと）
  1. 第1弾スコープ（スポーツTOPのみ／TOP+サッカー1種目）
  2. グロカテ統合 vs 独立軸（/theme/）の方向性 — エンジニア確認の事前合意
  3. スケジュール自動反映の実装範囲（初期は手動運用フェーズを置くか）
  4. 原稿担当（チーム内／外注）
