SECTION 01
なぜこの施策をやるのか
3つの戦略的根拠。データを見る前に施策の位置付けを理解する。
💡
2026年の設計原則は「情報の引き算」と「ユーザーの思考を止めない設計」。この施策は追加UIではなく、すでに存在する購入意欲を"見つけやすくする"改善として位置付ける。ノイズ除去・視認性向上という2025年の勝ちパターンと同じ原理だ。
🎯
理由① ファネルの2026年重点は「②回遊→③検討」
戦略上の重点フェーズであるACページ到達・カレンダー表示率の向上は、リピーターがすでに見ていたACに素早く戻れるかどうかに直結する。ヘッダーショートカットはファネル②③を最短で繋ぐ。
📊
理由② リピーターのCVRは新規の4倍以上——この層を動かすインパクトは大きい
リピーターは既にベルトラを信頼しており購入意欲は高い。問題は意欲ではなく「戻ったときの摩擦」。ここを削るだけで購入率が上がる。
⚙️
理由③ 2025年の勝ちパターンに沿っている
ハイライト非表示（+3.8%）・タブ切り替え化（+2%）・フローティングナビ化（positive）はいずれも「探索ステップを削って思考を止めない設計」。本施策も同じ原理で効果が期待できる。

SECTION 03
リピーターの行動分析と離脱ポイント
「なぜリピーターなのにACに到達できないか」を行動ストーリーで分解する。スクリーンショットの観察結果も含む。
STEP 01
🔍 再訪・着地
Organic / Direct / Emailでサイトに戻る。TOPページ、エリアページ、または検索結果に着地。
Direct CVR 2.98%は高いが、リピーターが必ずしもDirect経由で戻るわけではない
STEP 02
😐 新規と同じページを見る
ランキング・人気カテゴリ・特集—すべて初回ユーザーと同じ汎用コンテンツ。
⚠ 前回見たACを再発見する仕組みがない。記憶頼りの探索が始まる。エリアページ・カテゴリページには「最近チェック」セクション自体が存在しない。
STEP 03
🔄 スクロール探索
TOPページの「最近チェック」「保存リスト」は存在するがPCで画面3〜4枚分下。SPではハンバーガーメニューを開いてもパーソナライズなし。
⚠ ページ遷移（TOP→ハワイ→オアフ）のたびに情報がリセットされる。
STEP 04
💨 離脱 or 長い回遊
目的のACを再発見できないまま離脱。または長い回遊でようやくACに到達（時間と意欲の損失）。
💡 介入ポイント：ヘッダー常設ショートカットがあれば、どのページからでも1タップで戻れる
ページ観察から読み取れる具体的な課題
❌ Global TOP（PC/SP）
「最近チェック」「保存リスト」「あなたへのおすすめ」セクションは存在するが、ページ下部に埋もれている。ヘッダーには一切パーソナライズがない。
❌ ハワイ・オアフ島エリアTOP
ランキング・人気カテゴリ・限定キャンペーンと情報は豊富だが、ハワイを閲覧しているというコンテキストがヘッダーやメニューに一切反映されない。
❌ SPハンバーガーメニュー
メニューを開いても「ツアー・アクティビティ」「お気に入り」「マイページ」という汎用リンクのみ。ユーザーの文脈（今どこを見ているか、何に興味があるか）が完全に無視されている。
✅ 改善後のビジョン
ヘッダーのアイコン1つで「直近に見たAC」または「今見ているエリアの人気AC」がドロップダウンで表示される。どのページにいても1タップでACに到達できる。

SECTION 04
仮説設計
データと行動分析から導く3つの仮説。優先順に並べる。
H1
ヘッダーに「直近閲覧AC」ショートカットを置くと、リピーターのACへの到達ステップが減り、AC訪問率が上がる
現状、直近閲覧ACはTOPページ下部にしか存在しない。ヘッダーに常設されればエリアページ・カテゴリページ・検索結果のどこからでも1タップでACに戻れる。ステップ数の削減は直接的にAC到達率と購入率を改善する。
根拠：タブ化+2%・フローティングナビpositive・ハイライト非表示+3.8%はいずれも「ステップ削減＝思考を止めない設計」で効果が出た2025の勝ちパターン。同じ原理。
H2
閲覧URLに応じてエリア別ACを出し分けると、エリアページからのAC遷移率が上がる
ハワイエリアページを見ているユーザーに、ハワイの人気AC TOP3をヘッダーから提示する。「今見ているエリア×高評価AC」という文脈の一致がクリック意欲を高め、カテゴリページ→ACページの遷移率を改善する。
根拠：ハワイ・オアフ島のエリアページを確認したところ、ランキング等の情報は豊富だがヘッダーにエリア文脈がゼロ。UXの一貫性欠如が確認できた。
H3
Brazeで「カレンダー離脱ユーザー」をリターゲットすると、購入完了率が上がる
GTMで計測済みの view_calendar イベントを活用。カレンダーを開いたが48時間以内に未購入のユーザーに、次回ヘッダーを開いたとき「まだ空きあります」カードを表示する。購入直前の離脱を回収するシナリオ。
根拠：GTMの view_calendar イベントはすでに実装済み（P0イベント）。追加計測コストゼロでBrazeのトリガーに接続できる。3DS認証離脱（~4.8%/月）以外の離脱も一定数存在すると推定。
SECTION 05
打ち手とフェーズ計画
いきなりパーソナライズロジックを組むのは現実的でない。静的実装から始め、Brazeを経て段階的に高度化する。
PH
01
静的ショートカット — 閲覧歴＋URL文脈表示
仮説H1・H2を検証。サーバー連携ゼロで即実装可能。
工数: 小（3〜5日） AC到達率 +3〜5%想定 即時実装 フロントエンドのみ
Phase 1Aは直近閲覧AC（sessionStorage）をヘッダードロップダウンに表示。Phase 1Bは閲覧URLに応じてエリア別TOP3を静的JSONで差し込む。予約状況データ不要——サーバー連携ゼロで完結する。
💾
データ設計（1A）：sessionStorage に最大10件FIFO記録 ACページ閲覧時に id / name / url / thumbnailUrl / price / area を記録。セッション終了後はlocalStorageへ移行（30日保持）。個人情報なし。
🗺️
URL判定（1B）：エリアページ閲覧中にエリア別TOP3を静的JSON表示 /hawaii/ 配下 → ハワイ人気AC TOP3。エリアごとのJSONを週次更新するだけ。エンジニアなしでマーケが自己更新可能。
🔀
表示優先順位：閲覧歴 ＞ エリア文脈 ＞ 全体人気（fallback） sessionStorageに記録があれば閲覧歴を優先。なければURL判定でエリア別。それもなければ全体人気TOP3をデフォルト表示。
PH
02
Braze Content Cards — 閲覧行動トリガーでパーソナライズ
仮説H3を含む。予約データ不要。閲覧行動だけで動的配信。
工数: 中（2〜3週間） リピーター再予約率 +8〜15%想定 Phase 1効果確認後 Braze SDK + Content Cards
BrazeのURLトリガーでユーザーにタグを付与し、Content Cardsとしてドロップダウンに動的配信する。予約データは不要——閲覧行動だけでパーソナライズが完結し、Brazeダッシュボードから非エンジニアが配信内容を変更できる。
🏷️
URLイベントでBrazeタグ付与 GA4のpage_view → GTM → Brazeカスタムイベント。/hawaii/ 配下を2ページ以上閲覧 → "interested_hawaii" タグ付与（30日保持）。
⏰
カレンダー離脱リターゲット（仮説H3） GTM実装済みの view_calendar → 48h以内に未購入 → 「まだ空きあります」Content Cardをドロップダウン最上部に表示。追加計測コストゼロ。
🃏
Content Cardsとして描画。Brazeカードなしはフォールバック。 Phase 1のドロップダウン内にContent Cards APIスロットを追加。Brazeカード未設定時はPhase 1Aの閲覧歴に自動フォールバック。
PH
03
購入履歴ベース — 本格パーソナライズ
Phase 2の数字を確認してから投資判断。Q3以降。
工数: 大（1〜2ヶ月） リピートCVR維持・向上 Q3以降 Braze + API + Silver Egg
予約完了データをBrazeに連携し「前回購入エリア」「カテゴリ」に基づいてACをレコメンド。Silver Eggのレコメンドロジックとの連携も検討対象。Phase 2の数字（CTR・CVR変化）を見てから投資判断する。

実装メモ（Dev向け）
💾 Phase 1A: データ設計
  • ACページ閲覧時にsessionStorageへpush（最大10件FIFO）
  • キー: veltra_recent_acs（JSON配列）
  • セッション終了後 → localStorageへ移行（30日保持）
  • 個人情報なし・ログイン不要で動作
🎯 表示ロジックの優先順位
  • sessionStorage記録あり → 閲覧歴3件を表示（Ph.1A）
  • 閲覧歴なし + URL判定 → エリア別静的TOP3（Ph.1B）
  • どちらもなし → 全体人気TOP3（fallback）
  • Phase 2以降 → Braze Content Cardsで上書き
📊 GTM計測設計
  • header_recommend_open（ドロップダウン開閉）
  • header_recommend_click（ac_id / position / source）
  • source = recent | area | braze | default
  • ファネル: 開 → ACクリック → カレンダー → 購入
🟣 Braze設定（Phase 2）
  • GA4 page_view → GTM → Brazeカスタムイベント送信
  • URLパターン → interested_areas 属性更新（30日保持）
  • view_calendar後48h未購入 → urgencyカード先頭表示
  • Brazeカード未設定時 → Ph.1Aにフォールバック
