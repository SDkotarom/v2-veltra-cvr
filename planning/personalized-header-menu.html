SECTION 01
なぜこの施策をやるのか
3つの戦略的根拠。データを見る前に施策の位置付けを理解する。
🌏
【戦略背景：上長確認済み 2026-05-11】
円安・国際情勢により日本からの海外旅行は旅程が短期化する見込み。短い旅程 = メインの観光スポットしか回れない。 そのため全施策に共通する3つの設計軸は ①メインスポットのツアーで取りこぼさない、 ②迷わず買ってもらう、 ③その旅行中に使えるプラスアルファを追加購入してもらう。新規・リピーター共通。
💡
2026年の設計原則は「情報の引き算」と「ユーザーの思考を止めない設計」。この施策は追加UIではなく、すでに存在する購入意欲を"見つけやすくする"改善として位置付ける。ノイズ除去・視認性向上という2025年の勝ちパターンと同じ原理だ。
🎯
理由① ファネルの2026年重点は「②回遊→③検討」
戦略上の重点フェーズであるACページ到達・カレンダー表示率の向上は、リピーターがすでに見ていたACに素早く戻れるかどうかに直結する。ヘッダーショートカットはファネル②③を最短で繋ぐ。
📊
理由② リピーターのCVRは新規の4倍以上——この層を動かすインパクトは大きい
リピーターは既にベルトラを信頼しており購入意欲は高い。問題は意欲ではなく「戻ったときの摩擦」。ここを削るだけで購入率が上がる。
⚙️
理由③ 2025年の勝ちパターンに沿っている
ハイライト非表示（+3.8%）・タブ切り替え化（+2%）・フローティングナビ化（positive）はいずれも「探索ステップを削って思考を止めない設計」。本施策も同じ原理で効果が期待できる。
📌 この施策のスコープと対象外
✅ この施策がカバーすること
• リピーター（ログイン済み）がACへ戻る摩擦を削る
• 戦略軸②「迷わず買ってもらう」に直接貢献
• Phase 2以降でカレンダー離脱のリターゲット
❌ この施策が対応しないこと（別途検討）
• 新規ユーザーへのメインスポット訴求（戦略軸①）
• 購入後のプラスアルファ追加購入促進（戦略軸③）
• 未ログインユーザーへのパーソナライズ

SECTION 03
リピーターの行動分析と離脱ポイント
「なぜリピーターなのにACに到達できないか」を行動ストーリーで分解する。スクリーンショットの観察結果も含む。
STEP 01
🔍 再訪・着地
Organic / Direct / Emailでサイトに戻る。TOPページ、エリアページ、または検索結果に着地。
Direct CVR 2.98%は高いが、リピーターが必ずしもDirect経由で戻るわけではない
STEP 02
😐 新規と同じページを見る
ランキング・人気カテゴリ・特集—すべて初回ユーザーと同じ汎用コンテンツ。
⚠ 前回見たACを再発見する仕組みがない。記憶頼りの探索が始まる。エリアページ・カテゴリページには「最近チェック」セクション自体が存在しない。
STEP 03
🔄 スクロール探索
TOPページの「最近チェック」「保存リスト」は存在するがPCで画面3〜4枚分下。SPではハンバーガーメニューを開いてもパーソナライズなし。
⚠ ページ遷移（TOP→ハワイ→オアフ）のたびに情報がリセットされる。
STEP 04
💨 離脱 or 長い回遊
目的のACを再発見できないまま離脱。または長い回遊でようやくACに到達（時間と意欲の損失）。
💡 介入ポイント：ヘッダー常設ショートカットがあれば、どのページからでも1タップで戻れる
現状観察（実画面確認 — 2026-05-11）
🔍 重要な発見
ログイン後のメニュー（PC・SP共通）には既に「保存リスト」「閲覧履歴」のメニュー項目が存在。ただしカウント数（例：保存リスト 1、閲覧履歴 0）のテキストリンクのみで、実際のAC情報（画像・名前・価格）は出ていない。クリックして遷移しないと内容が見えない設計。
マイページには「あなたへのおすすめ」セクションも存在するが、閲覧履歴0のユーザーにもスパ系の静的コンテンツが表示されており、パーソナライズは機能していない。

つまり本施策は 新規UI追加ではなく、既存メニュー項目を「カウント→実物表示」に拡張する改善として位置付けられる。
❌ 現状：ログイン後メニュー（PC/SP共通）
保存リスト・閲覧履歴はテキスト＋カウントのみ。中身を見るには別ページへの遷移が必須。ヘッダー直下で再発見できない。
❌ 現状：マイページの「あなたへのおすすめ」
セクションは存在するが内容が静的（スパ系）。閲覧履歴0のユーザーにも同じ提案が出てしまい、パーソナライズ機能していない。
❌ 現状：エリアページのメニュー（ハワイ等）
ハワイ閲覧中にメニューを開いても汎用リンクのみ。エリア文脈がメニュー側に一切反映されない。
✅ 改善後：既存メニュー項目を実物表示に拡張
「閲覧履歴」「保存リスト」を、AC TOP3のサムネ・価格付きインライン表示に拡張。エリア閲覧中はその文脈に応じたACも追加表示。1タップでACに到達できる。

SECTION 04
仮説設計
データと行動分析から導く3つの仮説。優先順に並べる。
H1
既存メニューの「閲覧履歴・保存リスト」をカウント表示から実物TOP3表示に拡張すると、リピーターのACへの到達ステップが減り、AC訪問率が上がる
現状、ログイン後メニューには既に「保存リスト」「閲覧履歴」項目が存在するが、カウント数のみで実際のAC情報が出ていない（中身を見るには別ページ遷移が必要）。これをメニュー内で直接展開し、TOP3のサムネ・名前・価格を見せる。新規UI追加ではなく既存パターンの拡張のため、開発・デザイン負荷が低く、ユーザーの認知負担も小さい。
根拠：タブ化+2%・フローティングナビpositive・ハイライト非表示+3.8%はいずれも「ステップ削減＝思考を止めない設計」で効果が出た2025の勝ちパターン。同じ原理。
かつ「既存要素の拡張」のため、ユーザーが新規UIを学習する必要がない。
H2
閲覧URLに応じてエリア別ACを出し分けると、エリアページからのAC遷移率が上がる
ハワイエリアページを見ているユーザーに、ハワイの人気AC TOP3をヘッダーから提示する。「今見ているエリア×高評価AC」という文脈の一致がクリック意欲を高め、カテゴリページ→ACページの遷移率を改善する。
根拠：ハワイ・オアフ島のエリアページを確認したところ、ランキング等の情報は豊富だがヘッダーにエリア文脈がゼロ。UXの一貫性欠如が確認できた。
⚠ Phase 1の粒度はエリア単位（ハワイ全体）。戦略背景から本来必要なのは「メインスポット起点」の提案（例：キラウエアを見ているユーザーにハワイ島の関連ツアーを出す）。Phase 1Bの静的JSONをスポット単位に細分化することでここに近づける。Phase 2以降でBrazeの閲覧タグをAC単位に細かくすることで本格対応。
H3
Brazeで「カレンダー離脱ユーザー」をリターゲットすると、購入完了率が上がる
GTMで計測済みの view_calendar イベントを活用。カレンダーを開いたが48時間以内に未購入のユーザーに、次回ヘッダーを開いたとき「まだ空きあります」カードを表示する。購入直前の離脱を回収するシナリオ。
根拠：GTMの view_calendar イベントはすでに実装済み（P0イベント）。追加計測コストゼロでBrazeのトリガーに接続できる。3DS認証離脱（~4.8%/月）以外の離脱も一定数存在すると推定。
SECTION 05
打ち手とフェーズ計画
いきなりパーソナライズロジックを組むのは現実的でない。静的実装から始め、Brazeを経て段階的に高度化する。
❓ Q: 最初からBrazeを使えば？ Phase 1の静的実装は不要では？
A: Phase 1のUI改修はBrazeを使うとしても必須。並行実行が現実的。
Phase 1は「既存メニュー項目「閲覧履歴」「保存リスト」を実物表示に拡張する」UI改修であり、Brazeを使うかどうかとは独立に必要な作業。BrazeのContent Cardsも、このUIの「枠」に表示する形になる。

フェーズの実態：
  • Phase 1A：既存メニューのUI拡張＋既存閲覧履歴データを表示（フロントエンドのみ、3〜5日）
  • Phase 1B：URL文脈による静的JSON補完（Brazeのフォールバック用としても機能）
  • Phase 2：同じUIスロットにBraze配信ロジックを上乗せ（Brazeカードあり→Braze、なし→Phase 1の表示にフォールバック）
💡 推奨：Phase 1とPhase 2を並行で着手する。 Phase 1のUI改修は3〜5日で完成しリリース可能。同期間にBraze側でSDK確認・Content Cards設計・Brazeセグメント作成を進める。Phase 1リリース後 1〜2週間でBrazeカード配信開始の流れ。「静的→Braze」ではなく「UI先行、データソース後追い」と捉えるのが正確。
PH
01
既存メニュー拡張 — 閲覧履歴・保存リストの実物表示化＋URL文脈追加
仮説H1・H2を検証。既存UIの拡張のため新規学習コストなし。
工数: 小（3〜5日） AC到達率 +3〜5%想定 即時実装 フロントエンドのみ
Phase 1Aはログイン後メニュー内の既存「閲覧履歴」「保存リスト」項目を、カウントのみの表示からAC TOP3のサムネ・名前・価格を含むインライン展開に変更。Phase 1Bは閲覧URL（エリア／メインスポット）に応じた人気ACをメニュー内に追加セクションとして表示。サーバー連携ゼロで完結する。
🔧
既存メニュー項目の拡張（1A）：「閲覧履歴」「保存リスト」をインライン展開 既に存在するメニュー項目をそのまま使う。閲覧履歴メニューの下にTOP3のサムネ・AC名・価格を直接表示し、各行クリックで該当ACページへ。「すべて見る」リンクで既存の履歴ページにも遷移可能。データは既存の閲覧履歴データAPI（マイページから推測）or sessionStorageから取得。
💾
データ取得：既存履歴API優先、なければsessionStorage 既にバックエンドで閲覧履歴を保持している場合（マイページに閲覧履歴カウント表示があることから推測）、そのAPIを再利用。未提供ならsessionStorageに最大10件FIFOで記録（id / name / url / thumb / price / area）。個人情報なし。
🗺️
URL判定（1B）：エリア＋メインスポット単位で静的JSON表示 /hawaii/ 配下 → ハワイ人気AC TOP3。さらに /hawaii/oahu/ や個別ACページ（/a/キラウエア系）閲覧中はそのスポット関連ACを優先表示。JSONキーをエリアとスポットの2段階にすることで「メインスポット起点」の提案に近づける。エリアごとのJSONを週次更新するだけでエンジニアなし運用可能。
🔀
表示優先順位：閲覧履歴あり ＞ 保存リストあり ＞ エリア文脈 ＞ 全体人気 ログイン済みで閲覧履歴があればそれを最上部に。なければ保存リスト。どちらもなければURL判定でエリア／スポット別。それもなければ全体人気TOP3。マイページの「あなたへのおすすめ」も将来的に同ロジックに統一し、閲覧履歴ゼロでスパが出る現状を解消する。
PH
02
Braze Content Cards — 閲覧行動トリガーでパーソナライズ
仮説H3を含む。予約データ不要。閲覧行動だけで動的配信。
工数: 中（2〜3週間） リピーター再予約率 +8〜15%想定 Phase 1効果確認後 Braze SDK + Content Cards
BrazeのURLトリガーでユーザーにタグを付与し、Content Cardsとしてドロップダウンに動的配信する。予約データは不要——閲覧行動だけでパーソナライズが完結し、Brazeダッシュボードから非エンジニアが配信内容を変更できる。
🏷️
URLイベントでBrazeタグ付与 GA4のpage_view → GTM → Brazeカスタムイベント。/hawaii/ 配下を2ページ以上閲覧 → "interested_hawaii" タグ付与（30日保持）。
⏰
カレンダー離脱リターゲット（仮説H3） GTM実装済みの view_calendar → 48h以内に未購入 → 「まだ空きあります」Content Cardをドロップダウン最上部に表示。追加計測コストゼロ。
🃏
Content Cardsとして描画。Brazeカードなしはフォールバック。 Phase 1のドロップダウン内にContent Cards APIスロットを追加。Brazeカード未設定時はPhase 1Aの閲覧歴に自動フォールバック。

実装メモ（Dev向け）
💾 Phase 1A: データ設計
  • ACページ閲覧時にsessionStorageへpush（最大10件FIFO）
  • キー: veltra_recent_acs（JSON配列）
  • セッション終了後 → localStorageへ移行（30日保持）
  • 個人情報なし・ログイン不要で動作
🎯 表示ロジックの優先順位
  • sessionStorage記録あり → 閲覧歴3件を表示（Ph.1A）
  • 閲覧歴なし + URL判定 → エリア別静的TOP3（Ph.1B）
  • どちらもなし → 全体人気TOP3（fallback）
  • Phase 2以降 → Braze Content Cardsで上書き
📊 GTM計測設計
  • header_recommend_open（ドロップダウン開閉）
  • header_recommend_click（ac_id / position / source）
  • source = recent | area | braze | default
  • ファネル: 開 → ACクリック → カレンダー → 購入
🟣 Braze設定（Phase 2）
  • GA4 page_view → GTM → Brazeカスタムイベント送信
  • URLパターン → interested_areas 属性更新（30日保持）
  • view_calendar後48h未購入 → urgencyカード先頭表示
  • Brazeカード未設定時 → Ph.1Aにフォールバック
