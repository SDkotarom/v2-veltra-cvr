SECTION 02
レコメンドロジック詳細 — Brazeで実現する方法
「どんなレコメンドを、どういう条件で、どう表示するか」を全て具体化。レコメンドシステムは作らず、Brazeのカスタム属性とセグメントだけで実現する。
⚙️
本施策はMLレコメンドではない。Brazeの標準機能（カスタムイベント／カスタム属性／セグメント／Content Cards／Liquidテンプレート）だけで動作するルールベース＋個人属性のハイブリッド設計。
A. DATA COLLECTION
ステップ1：Brazeに送る3つのイベント
1
ACページ閲覧時
ACページが表示されたら、AC情報をパラメータ付きでBrazeに送信。
braze.logCustomEvent("viewed_ac", {
  ac_id, ac_name,
  ac_thumbnail_url,
  ac_price, ac_url,
  ac_rating, area
})
2
カレンダー開示時
既存GTMの view_calendar イベントをBrazeにも送信開始。AC情報を含める。
braze.logCustomEvent("view_calendar", {
  ac_id, ac_name,
  ac_thumbnail_url,
  ac_price, ac_url
})
3
購入完了時
予約完了時に購入情報を送信。購入履歴ベース配信（カードD）で活用。
braze.logCustomEvent(
  "ecommerce_purchase", {
  ac_id, area, category,
  purchase_at
})
Braze側で起こること：これらのイベントを受信するたび、Braze内部でユーザー属性が自動更新される。例えば viewed_ac 受信時は last_viewed_ac_1_* 属性に最新ACを保存し、古い値は last_viewed_ac_2_* → last_viewed_ac_3_* へとシフトする（Brazeの「Update User Attribute via Event」アクションで設定）。
B. CARD SPECIFICATIONS
ステップ2：3つのカードの詳細仕様
⓪ どうやって表示する AC を選ぶか
カード何を出すか選び方ロジック
CARD A
閲覧履歴		 本人が直近に見た 3 件 新しい順（時系列）。Braze の last_viewed_ac_1/2/3_* をスライド更新するだけ。「見た回数が多い順」ではない
CARD B
エリア人気		 そのエリアの「ルールベース上位 AC」5件 3条件のAND で月次バッチ自動選定：①直近30日 page_view 上位／②⭐ 4.0 以上＆体験談 10件以上／③営業中。個人の視聴回数ベースでは動かない。出し分けは「どのエリアのリストを見せるか」だけ（ハワイ閲覧者→ハワイリスト 等）。マーケは「除外フィルタ」だけかける（不適切掲載・季節終了等）
CARD C
カレンダー離脱		 本人がカレンダー開いたが買わなかった、その AC レコメンドではなく本人リターゲット。48 時間以内に view_calendar 発火＋未購入のとき、その AC をそのまま再表示する
ポイント：個人の視聴を使っているのは カード A（時系列）と C（リターゲット）のみ。B は「ルールベースで全ユーザー共通の人気上位5件」をエリアごとに自動選定（GA4 + 在庫DB の月次バッチ、マーケは除外フィルタのみ）。視聴回数 → スコア化 → レコメンドエンジン的な個人最適化はこの段階では入れていない（外部レコメンド API 連携の領域）。
CARD A
⏱ 閲覧履歴TOP3
優先度 Medium
配信対象（セグメント）
last_viewed_ac_1_id が存在する AND ログイン済みユーザー
データソース
Brazeカスタム属性 last_viewed_ac_1_* / 2_* / 3_*（viewed_acイベント受信時に自動シフト更新）
表示内容
Liquidテンプレートで属性値を動的に展開。3件のAC情報（サムネ・名前・価格・URL）をリスト表示。
マーケ管理範囲
テンプレートのデザイン・文言のみ。コンテンツ（どのACが表示されるか）は完全自動。
更新タイミング
ユーザーがACページを閲覧するたびリアルタイムに更新。次回メニュー開示時に反映。
CARD B
🌺 エリア人気AC（ルールベース自動選定）
優先度 Medium-Low
配信対象（セグメント）
過去7日間に page_view イベントで対象エリアURL（例：/hawaii/ 配下）を2回以上閲覧したユーザー。Brazeでエリア別にセグメントを作成。
初期テスト4エリア
ハワイ・韓国・グアム・タイ（海外特化）でスタート。
選定理由：(1) 戦略軸「海外旅行短期化」と整合（円安下でも需要が見込めるリピーター主戦場）／(2) いずれもエリアTOPセッション数で上位 (ハワイ40K・韓国13K・グアム9K)＋タイは情勢回復で伸び期待／(3) 季節依存が低くテスト品質が安定（富山・屋久島など季節限定エリアは除外）／(4) リピーター比率が高くカード B の効果が出やすい
AC 選定ロジック
（3条件の AND）
① トラフィック条件：エリア配下AC ページの直近30日 page_view 上位
② 品質条件：⭐ 4.0 以上 ＆ 体験談 10件以上
③ 販売状態：営業中（販売停止・季節終了・天候停止は除外）
上記AND を満たす上位5件を「そのエリアの人気AC」として表示（A/B で TOP3 vs TOP5 を検証）
運用フロー
月次バッチで GA4 + 在庫DB から候補リストを自動生成 → スプレッドシート出力 → マーケは「不適切掲載の除外」のみ（30分作業）→ Braze Content Card 用 JSON にエクスポート。"マーケが手で選ぶ"作業は発生しない
「人気」定義の A/B 検証
案A（page_view 上位＝注目）／案B（購入数上位＝実売）／案C（wishlist 追加上位＝欲しがられている）を Braze ダッシュボード上で並行検証。初期は案A、結果を見て切替
CARD C
⏰ カレンダー離脱リターゲット
優先度 HIGH（最上部表示）
配信対象（セグメント）
過去48時間以内に view_calendar を発火 AND その後に ecommerce_purchase なし
データソース
Brazeカスタム属性 calendar_abandon_ac_* と calendar_abandon_at（view_calendarイベント受信時に保存、購入完了時にクリア）
表示内容
「⏰ あのアクティビティ、まだ空いています」見出し＋離脱したAC情報。メニュー最上部に表示（priority設定）。
有効期限
48時間で自動的にセグメントから外れる。購入完了でも即座にクリア。
マーケ管理範囲
見出し文言とデザインのみ。AC情報は自動。
カードの優先順位ロジック：① C（緊急性・購入直前）→ ② A（最も個人化）→ ③ B（文脈依存）→ ④ フォールバック（全体人気AC）。BrazeのContent Cards priority設定で制御。

D. PARALLEL A/B TEST
ステップ4：Braze ダッシュボードで A/B を並行運用
⚡
Phase 分割せず、3カード（A・B・C）をローンチ時点で全部稼働させ、Braze ダッシュボード上で A/B テストを並行運用する。開発作業は Week 1 の 5日のみ。以降は Braze 内のセグメント・カード・Liquid を編集するだけで、複数の検証が同時並行で回せる。
並行で回す A/B テスト例（ローンチ後 4週目以降）
  • カードA（閲覧履歴）：TOP3 を表示するか／TOP5 を表示するか／「同エリア人気を併記」するか
  • カードB（エリア人気）：初期4エリア（ハワイ・韓国・グアム・タイ）でスタート、稼働後にスポット粒度（30+）を段階追加して並走させ CTR で比較
  • カードC（カレンダー離脱）：コピー違い（「まだ空きあります」/「あと◯日で満席の可能性」）、48h vs 72h のトリガー時間差
  • カード優先度：3カードの並び順（離脱C → 履歴A → エリアB） vs（履歴A → 離脱C → エリアB）の比較
  • 追加カード D（購入履歴ベース）：初期から仕込んで「前回ハワイで購入したあなたへ」も並行検証（last_purchase_area 属性使用）
Braze で並行運用するメリット：カード・セグメント・テンプレートが独立してるので、複数の A/B を同時に回しても干渉しない。開発を待たずに、データが出た順番に「勝ち variant」を採用してダッシュボードで切り替えるだけ。「順次フェーズ展開」ではなく「全カード並走 + 継続最適化」が Braze 運用の正しい姿。

現状の課題（実画面確認 2026-05-11）
  • 既存メニューはカウントのみ。「保存リスト 1」「閲覧履歴 0」などテキスト＋数字だけで実物が見えない
  • マイページの「あなたへのおすすめ」はパーソナライズ機能していない。閲覧履歴0でもスパが表示される静的コンテンツ
  • エリアページのメニューに文脈なし。ハワイ閲覧中でも汎用リンクのみ
  • 結果：リピーターは再訪→汎用ページ→記憶頼りの探索→離脱、または長い回遊で失速
なぜ取り組むか
  • 2026重点は ②回遊→③検討。AC到達・カレンダー表示率の改善がここに直結
  • リピーターCVRは新規の4.4倍。意欲は高く、戻った時の摩擦が問題
  • 2025勝ちパターンと同原理。ステップ削減型UX改善（タブ化+2%等）
  • Braze活用で開発依存最小化。半日〜1日のFE作業のみ、以降はダッシュボード運用
🌏
戦略背景（上長確認済 2026-05-11）：円安・情勢変化で海外旅行は短期化傾向。全施策共通の3軸＝①メインスポット取りこぼし防止／②迷わず買う／③滞在中のプラスアルファ購入。新規・リピーター共通。

❌ 対象外：新規向けメインスポット訴求（軸①）／購入後のクロスセル（軸③）／未ログイン ← 別施策で検討
