SECTION 01
実装方法の全体マップ
「誰が」「どこで」「何を」やるかを最初に決めておく。Braze Content Card は 開発側に頼らずマーケが回せる範囲が広い のが特徴で、4シナリオも基本は Braze Dashboard 上で完結する。開発が必要なのは「初回のイベント送信実装」と「描画コンテナの設置」だけ。
A. RESPONSIBILITIES
誰が何をやるか
開発 / Engineering
  • Braze SDK 初期化 (GTM経由)
  • カスタムイベント送信実装 (viewed_ac / view_calendar / ecommerce_purchase)
  • 描画コンテナ配置 (#braze-content-cards)
  • traveler_id を Braze に連携
マーケ / Marketing
  • Brazeダッシュボードでカード作成
  • KVP / Liquid テンプレート設計
  • セグメント定義
  • Catalogs CSV 月次更新
  • 配信トリガー・優先度設定
PJM / Strategy
  • シナリオ優先度の決定
  • KPI 設計・モニタリング
  • A/B 結果の意思決定
Braze SDK
  • イベント記録
  • 属性更新
  • カード同期 (sessionスタート / 1分以上経過 / 明示refresh)
  • Impression/Click/Dismiss 自動ログ
GTM
  • Braze SDK init スクリプト管理
  • カスタムHTMLタグ発火
  • 環境分離 (prod/dev)
  • マーケが直接書き換え可
B. DATA FLOW
データの流れ (一般形)
App / Site
>
ユーザー行動が発生 (AC閲覧 / カレンダー開示 / 購入完了 / エリア閲覧)
Braze SDK
>
logCustomEvent() でイベント送信 (例: viewed_ac with ac_id, ac_name, ac_thumb, ac_price...)
Braze Server
>
Workflow が起動 → カスタム属性を更新 (例: last_viewed_ac_1_* をスライド)。または Catalogs を参照してフィルタリング
Braze Server
>
セグメント条件マッチ判定 → 対象ユーザーに Content Card を配信キュー
Braze SDK
>
セッション開始 or requestContentCardsRefresh() でカードを取得 → Liquid テンプレートが属性値を埋め込んで展開
App / Site
>
braze.toggleContentCards(parentNode) で描画コンテナにカード表示。Impression/Click/Dismiss は SDK が自動ログ
SECTION 02
UI 実装レベルの選択
Braze Content Card は描画 UI を 4 段階でカスタマイズできる。実装工数と Analytics 自動化のトレードオフ。今回の 4 シナリオは 全て Style or UI レベルで実装可能 (Default UI のままだと VELTRA ヘッダーメニュー内の見た目に馴染まないため)。
Default
そのまま使う (右サイドバーフィード)
工数最小 / Analytics自動。今回はサイドバー表示ではなくヘッダーメニュー内に埋め込むため非採用。
非採用
Style
CSS だけ上書き
描画コンテナを parentNode 指定で配置し、CSS でメニュー内に馴染ませる。テキスト/画像の差し替えは KVP で対応。Analytics 自動。初期ローンチはこれで十分。
第一候補
UI
カードの HTML 構造ごと差し替え
独自テンプレで描画 (カード A の 3 件並び等)。Analytics 自動維持。Style では足りない場合のフォールバック。
必要時
UX
SDK UI を使わず payload だけ受けて自社描画
完全自由だが logContentCardImpression / Clicked / Dismissed / Displayed を手動実装必須。記録漏れ事故リスクあり。初期は採用しない。
非推奨
SECTION 03
Card A — 閲覧履歴 TOP3 の実装
Traveler が直近に閲覧した AC を新しい順に 3 件表示。最もシンプル＆コア。データ蓄積待ち不要、1 件閲覧で即発火。
CARD A
閲覧履歴 TOP3
priority = 6
データソース
Data Source
カスタムイベント viewed_ac (AC ページ閲覧時に発火)。
パラメータ: ac_id / ac_name / ac_thumbnail_url / ac_price / ac_url / ac_rating / area
属性スキーマ
Attribute Schema
Braze カスタム属性を以下の命名で保持 (1〜3 をスライド更新):
last_viewed_ac_1_id // 最新 last_viewed_ac_1_name last_viewed_ac_1_thumb last_viewed_ac_1_price last_viewed_ac_1_url last_viewed_ac_2_* // 1つ前 last_viewed_ac_3_* // 2つ前
属性更新ロジック
Update Workflow
Braze Canvas (Workflow) で viewed_ac 受信時に下記を実行:
  1. last_viewed_ac_2_* → last_viewed_ac_3_* へコピー
  2. last_viewed_ac_1_* → last_viewed_ac_2_* へコピー
  3. 新着AC情報を last_viewed_ac_1_* に書き込み
(Braze の "Update User Attribute via Event" アクションでステップ実装)
セグメント条件
Segment
last_viewed_ac_1_id が 存在する AND ログイン済み
Liquid テンプレート
Liquid Template
{% if {{custom_attribute.${last_viewed_ac_1_id}}} %} <div class="viewed-ac-list"> <a href="{{custom_attribute.${last_viewed_ac_1_url}}}"> <img src="{{custom_attribute.${last_viewed_ac_1_thumb}}}"> <span>{{custom_attribute.${last_viewed_ac_1_name}}}</span> <span class="price">¥{{custom_attribute.${last_viewed_ac_1_price}}}</span> </a> {% if {{custom_attribute.${last_viewed_ac_2_id}}} %} ... (同上 _2_*) {% endif %} {% if {{custom_attribute.${last_viewed_ac_3_id}}} %} ... (同上 _3_*) {% endif %} </div> {% endif %}
トリガー
Trigger
Start Session In Any App。"no re-eligibility" にチェック
配信頻度
Cadence
セグメント所属中は常時表示。last_viewed_ac_* の更新がリアルタイムに反映 (次回メニュー開示時)
マーケが触る範囲
Marketing Scope
テンプレートのデザイン・文言のみ。AC選定は完全自動 (新着3件)
必要な開発
Dev Effort
AC ページに braze.logCustomEvent("viewed_ac", {...}) を追加 (1日)
SECTION 04
Card B — エリア人気 AC の実装
特定エリアを閲覧中の Traveler に、そのエリアの「品質上位 5 件」を表示。個人視聴ではなく Braze Catalogs で全 Traveler 共通のリストを持つルールベース選定。
CARD B
エリア人気 AC (Catalogs ベース)
priority = 4
データソース
Data Source
既存 GA4/dataLayer の page_view イベント (URLパス含む)
＋ Braze Catalogs (AC マスタ CSV)
Catalog スキーマ
Catalog Schema
Braze Dashboard に CSV をアップロード:
id,name,thumb,price,rating,review_count,area,status,url "AC123","イルカと泳ぐ","https://...",17820,4.82,156,"hawaii","active","https://..." "AC456","ダイヤモンドヘッド","https://...",10154,4.54,203,"hawaii","active","https://..."
エリアセグメント
Area Segment
過去 7 日に対象エリア URL を 2 回以上閲覧した Traveler
例: "Hawaii Interest" = page_view event count where URL contains '/hawaii/' >= 2 in last 7 days
初期対象 4 エリア: ハワイ・韓国・グアム・タイ
Liquid 絞り込み
Catalog Query
{% catalog_items 'ac_master' where: 'area=hawaii AND rating>=4.0 AND review_count>=10 AND status=active' sort: 'rating_score desc' limit: 5 %} <div class="area-popular-list"> {% for item in catalog_items %} <a href="{{ item.url }}"> <img src="{{ item.thumb }}"> <span>{{ item.name }}</span> <span class="meta">⭐ {{ item.rating }}</span> <span class="price">¥{{ item.price }}〜</span> </a> {% endfor %} </div>

rating_score = rating × review_count の計算列を Catalog 側に持たせる (または CSV に事前計算)

トリガー
Trigger
Start Session。エリアごとに 4 つのキャンペーンを並走
運用フロー
Operation
月次に CSV を Braze にアップロード (マーケが Dashboard で実行、開発不要)。Catalog 更新後は次回配信から新リストで Liquid が展開
マーケが触る範囲
Marketing Scope
Catalog 更新 (月次) ／ Liquid テンプレートのデザイン ／ エリアの追加 ／ 絞り込み条件の調整 (rating 閾値等)
必要な開発
Dev Effort
既存 page_view を Braze SDK にも送る (1日)
+α 開発で広がる
Optional Dev
GA4 BigQuery export → Cloud Functions で「直近30日 page_view 上位」を Catalog 列に流し込む。選定条件に 人気度軸が加わる (5〜7 日)。初期は不要
SECTION 05
Card C — カレンダー離脱リターゲットの実装
「カレンダーを開いて 48 時間以内に未購入」という最強の購入意欲シグナルを掴んだ Traveler に、その AC をそのまま再提示。priority = 10 で最上位表示。
CARD C
カレンダー離脱リターゲット (最優先)
priority = 10
データソース
Data Source
既存 GTM の view_calendar イベントを Braze にも送信開始
＋ 既存 ecommerce_purchase
イベント実装
Event Payload
braze.logCustomEvent("view_calendar", { ac_id, ac_name, ac_thumb, ac_price, ac_url, opened_at });
属性スキーマ
Attribute Schema
calendar_abandon_ac_id calendar_abandon_ac_name calendar_abandon_ac_thumb calendar_abandon_ac_price calendar_abandon_ac_url calendar_abandon_at // timestamp
属性更新ロジック
Update Workflow
  • view_calendar 受信 → 上記属性を上書き保存 (最新のカレンダー開示AC)
  • ecommerce_purchase 受信 → 該当ACなら属性をクリア
  • 48時間経過後はセグメント条件で自動的に対象外 (属性自体は残るが配信されない)
セグメント条件
Segment
calendar_abandon_at が 過去 48h 以内 AND calendar_abandon_ac_id が存在する AND ecommerce_purchase event count for that ac_id = 0
Liquid テンプレート
Liquid Template
<div class="calendar-abandon"> <div class="alert-label">あのアクティビティ、まだ空いています</div> <a href="{{custom_attribute.${calendar_abandon_ac_url}}}"> <img src="{{custom_attribute.${calendar_abandon_ac_thumb}}}"> <span>{{custom_attribute.${calendar_abandon_ac_name}}}</span> <span class="urgency">残り少ない</span> <span class="price">¥{{custom_attribute.${calendar_abandon_ac_price}}}〜</span> </a> </div>
トリガー
Trigger
Start Session ／ view_calendar 直後にも別キャンペーンで即時配信可
マーケが触る範囲
Marketing Scope
見出し文言・コピー (「まだ空いています」vs 「あと◯日で満席の可能性」等)、デザイン、トリガー時間 (48h vs 72h)
必要な開発
Dev Effort
既存 GTM view_calendar を Braze にも送る GTM タグ追加 (0.5日)
SECTION 06
Card D — 購入履歴ベースの実装
過去購入エリアの「品質上位 5 件」をリピート訴求。Card B の Catalogs ロジックを購入エリアに適用するだけで実装できる。
CARD D
購入履歴ベース (前回購入エリアの上位)
priority = 8
データソース
Data Source
既存 ecommerce_purchase イベント
＋ Card B と同じ Catalogs
属性スキーマ
Attribute Schema
last_purchase_area // 例: "hawaii" last_purchase_at // timestamp
属性更新ロジック
Update Workflow
  • ecommerce_purchase 受信 → area パラメータを last_purchase_area に保存
  • last_purchase_at から 90 日経過 → セグメント条件で自動的に対象外
セグメント条件
Segment
last_purchase_area が 存在する AND last_purchase_at が 過去 90 日以内。エリアごとに分岐セグメント
Liquid テンプレート
Liquid Template
{% assign area = {{custom_attribute.${last_purchase_area}}} %} {% catalog_items 'ac_master' where: 'area={{area}} AND rating>=4.0 AND review_count>=10 AND status=active' sort: 'rating_score desc' limit: 5 %} <div class="repeat-purchase"> <div class="heading">前回{{area}}で購入したあなたへ</div> {% for item in catalog_items %} <a href="{{ item.url }}"> <img src="{{ item.thumb }}"> <span>{{ item.name }}</span> <span class="price">¥{{ item.price }}〜</span> </a> {% endfor %} </div>
トリガー
Trigger
Start Session。エリアセグメントごとにキャンペーン分岐
マーケが触る範囲
Marketing Scope
見出し文言 (「前回ハワイで購入したあなたへ」「次のハワイ旅行はもう決めましたか？」等)、配信スケジュール。AC選定リストは Card B と同じ自動選定
必要な開発
Dev Effort
既存 ecommerce_purchase に area パラメータが入っているか確認のみ (実装は基本不要)
SECTION 07
共通の運用手順
4 シナリオ全てに共通する設定・確認・運用ルール。Braze ダッシュボード上で完結する。
7.1 PRIORITY
カード並び順 (priority マトリクス)
順カードpriority値なぜこの順か
1C 離脱10カレンダーを開いて 48h 未購入＝もうすぐ買いそうシグナルが最強。最上部
2D 購入履歴8過去に購入経験あり＝支払い意欲・サイト信頼が確認済み
3A 閲覧履歴6本人が直接見ていた AC。再到達ニーズ高い
4B エリア人気4エリアに来ているだけで本人の意欲は不明。探索補助
5フォールバック2上記いずれも発火しない時の汎用「全体人気 AC」
NOTE
設定箇所。各 Content Card キャンペーンの設定画面で「priority」整数を割り当て。Braze SDK が同一ユーザーに該当する全カードを priority 降順で並べて返す。Dashboard で値を変えればリアルタイムで切替可能 (デプロイ不要)。A/B で順番違いも検証できる。
7.2 EXPIRATION
有効期限管理
カードキャンペーン DurationCard Expiration (Time in Feed)
A 閲覧履歴無期限 (常時稼働)7 日 (1週間で古い履歴は不要)
B エリア人気無期限 (常時稼働)30 日 (Catalog 月次更新と整合)
C 離脱無期限 (常時稼働)3 日 (セグメントが 48h で自動失効するためバッファ込み)
D 購入履歴無期限 (常時稼働)30 日
CAUTION
キャンペーン終了日 ≠ カード有効期限。キャンペーンが終了してもすでに配信済みカードは Feed 内に "Time in Feed" の日数だけ残る。終わったはずなのに見える、を防ぐため両方を意識的に設定する。1 カード 2KB 制限・Feed 内 100 件上限も忘れずに。
7.3 CURRENTS
Currents 4 イベント記録の確認

UI レベルが Default / Style / UI のいずれかであれば、下記 4 イベントは SDK が自動でログする。UX レベルだと手動実装が必須。

  • users.messages.contentcard.Send — Braze サーバが配信キューに入れた時点
  • users.messages.contentcard.Impression — ユーザーがカードを閲覧した時点
  • users.messages.contentcard.Click — ユーザーがカードをクリックした時点
  • users.messages.contentcard.Dismiss — ユーザーがカードを閉じた時点

Currents export を BigQuery / Snowflake 等につないでおくと、カード別 CTR / Impression-to-CVR を Braze 外でも分析可能。

7.4 A/B PARALLEL
A/B テストの並走構造

Phase 分割せず、4 カード × 4 エリア (× variant) を一斉稼働させる。カード・セグメント・テンプレートが独立してるので干渉しない。

テスト軸例
A コピー「閲覧履歴 TOP3」 vs 「最近見た AC」
B 表示順C → D → A → B の固定順 vs 動的優先度
C トリガー時間48h vs 72h vs 24h でカレンダー離脱の最適時間を探る
D 訴求文言「前回ハワイで購入したあなたへ」vs 「ハワイのリピーター限定」
エリア粒度初期 4 エリア vs スポット粒度 (30+) で CTR 比較
WIN PATTERN
運用方針。Braze の variant 機能で各カードに A / B variant を立て、Currents の CTR を週次レビュー → 勝ち variant をダッシュボード上で採用切替。開発を待たずに継続最適化が回る。
