01Conclusion — 結論
W19 / GW後半週・データ品質インシデント継続
GW 後半に入り セッションは +5.9%（937K → 992K）に増えたのに、予約完了は -15.2%（12,003 → 10,175件）と逆方向に動き、
CVR は 1.28% → 1.03%（-0.26pt）に後退。 ただしこれは「ユーザーが買わなくなった」のではなく、Singapore × Chrome × Windows bot が依然 19.7%（195K/週）流入し続けて分母を希釈しているのが主因。 bot 除外で見た「実ユーザー CVR」は 1.27%（28日ベース）で W18 から大きく崩れていない。
加えて ②→③（AC到達→検討）が WoW -2.52pp 悪化し、GW 連休の旅行計画モードから日常モードへ切り替わる過渡期で「カレンダーを押す手前で止まる」層が増えているのが今週の構造変化。
WAF 運用の事実確認 + 実ユーザー指標での経過観察 + Top3 ボトルネック継続実装の3本立てが今週のテーマ。
W19 は GW の重心日（5/3 Sun〜5/6 Wed の4連休 + 5/7〜5/9 の3営業日）を含む過渡週。 (1) bot 状況 — Singapore × Chrome × Win bot は 28日で 774K セッション（19.7%）／週次で 195K セッション残存。 W18 までの観察から WAF ブロックが入った可能性を疑っていたが、W19 を見る限り bot 流入は減っていない。WAF ルール適用状況の事実確認が優先。 (2) 実ユーザー指標 — bot 除外 28日 CVR は 1.327%（rawは 1.066%）で、前年同月（2025-05 月次 CVR 1.404%）との差は -0.08pp まで縮む。「見かけの崩れ」と「実態の崩れ」を分けて読む。 (3) ②→③ -2.52pp — 5/3-5/6 の GW 重心日は「予約検討」のピーク、5/7-5/9 は通常モードに戻る過渡。 AC ページから予約カレンダーを開く行動の鈍化は、GW の反動なのか恒常変化なのか W20 で見極める。
構造ボトルネック Top3 は W16/W17/W18/W19 と 4 週連続同じ顔ぶれ: BN1 新規 ④→⑤、BN2 モバイル ①→②、BN3 リピーター ①→②。GW 後の繁忙期に向け、Quick Wins から実装を進める時期に入っている。

W19 28日 raw データは sessions 3.94M / 購入 41,985 / CVR 1.066% で、見かけは前年同月（2025-05 1.404%）から -0.34pp 沈んでいる。 しかしSingapore × Chrome × Win bot 774,241 セッションを除外すると 28日 sessions 3.16M / 購入 41,970（-15件のみ）/ CVR 1.327%と、前年同月との乖離は -0.08pp まで縮まる。 前年同月 2025-05 もリゾート GW シーズンの相対的に低めの CVR 月（前年同月のYoY水準 baseline 1.404% に対し近年トレンドは 1.4〜1.5% レンジ）なので、「実ユーザーは前年水準から大きく崩れていない」と判断できる。 この週の数字を経営層に報告する際は 「raw 1.07% / bot 除外 1.33% / 前年水準 1.40%」の3点を併記する運用を W17 で宣言済み。kpi.html への bot 除外トグル実装は来月の月次確定までに完了させる。
03Action — やるべきこと
WAF 運用の事実確認 + 構造課題 BN1-3 の実装フェーズ移行 + ②→③ 単週谷の継続観察
「データ品質を直す」「数字を作らずに来る本物のユーザーに効く施策を入れる」「単週の谷は来週まで様子見」の3本立て。W19 で構造課題は明確に固着が確認されたので、議論より実装に資源を寄せる時期。

CHECK / 緊急 WAF / インフラ運用確認 優先度: 最高
WAF Singapore × Chrome × Windows ルールが本当に動いているのか事実確認 — bot 195K/週が抜けてきている
W18 サマリーで 「WAF ブロックが運用に入っている可能性が高い」と書いたが、W19 では bot 流入が 19.7%（195K/週）で W18 と同水準のまま継続しており、結果から見て WAF ルールはまだ効いていない。 Mayumi さん／インフラチームへ 「WAF Singapore × Chrome × Win ルールの現在のステータス（適用済か未適用か）／ブロック数の推移／除外条件」を即日確認。 未適用なら 5月の GW 後繁忙期と前年同月比較が両方汚れるため、最優先で適用着手。適用済なのに数字が変わっていないなら、bot 側がルールを回避している＝検知条件を更新する必要あり。
ステップ: ① WAF ルール現在のステータス／ブロック数を確認（半日）② 未適用なら適用日程を Mayumi さんと合意（1日）③ 適用済なら 5/4 のスパイク 77K が抜けた理由を追加調査（1日）④ kpi.html に bot 除外トグル実装の優先度を上げる（来月確定までに完了）
2
既存 BN Top3 / 実装フェーズ移行 UX / フォーム / リピーター動線 / モバイル探索 優先度: 高
構造課題 4 週固着確認 — BN1 / BN2 / BN3 の Quick Wins を Sprint 計画へ正式投入
W16 / W17 / W18 / W19 の 4 週連続で Top3 が同じ顔ぶれであることが確定。これは「議論を続けても動かない構造課題」のシグナルで、Quick Wins（effort=S・制約なし）から実装フェーズへ移行するタイミング。 BN1（新規 ④→⑤）と BN2（モバイル ①→②）は月50〜60万人規模に効き、施策化レビュー Step 5 の audit で effort=S かつ重複なしの Quick Wins が複数特定済み。MIB 開発の次 Sprint（5/12-5/23）へ 3 件をスコープ確定。 並行で BN3（リピーター ①→②）は GW 後にリピーター層がもう一度動く可能性が残るため、ウィッシュリスト・最近見た AC の再表示系を先行 A/B 投入。
BN1: 新規ユーザーが『長いフォーム＋最終価格の不意打ち』で決済直前に諦めている（新規 ④→⑤ -24.3pp / 月63万人影響）
BN2: モバイルで『自分に合うAC』を見つけられず、比較疲れで離脱している（モバイル ①→② -24.7pp / 月52万人影響）
BN3: リピーターが『前回見たAC』を思い出せず、探し疲れで離脱している（リピーター ①→② -28.6pp / 月35万人影響）
